# Сверловка: InsertWeldWithHoles, COPY_VIEW_R6_DIMENSIONS

BUILD_ID: `DRILL_COPY_VIEW_R6_DIMENSIONS_20261029`.

Исправляется только модуль `InsertWeldWithHoles` из пользовательского
`Сверловка.swp`. Остальные модули, классы и макросы объединения чертежей
V16.* не меняются. Извлечённый исходный модуль — в `original/`, UTF-8.

**Статус R6:** синтаксис и отдельные расчёты/правила проверены в Linux;
нативный Compile/запуск ещё не выполнен. Пользователь подтвердил работу R3
на одном примере, затем показал Error 457 при снимке видов на другом запуске.
Это ограниченное подтверждение, не доказательство исправности всех случаев.
Журнал R4 затем подтвердил повтор GetUniqueName=*Спереди у двух перечисленных
ссылок; R4 не работает на этом чертеже. R5 устраняет зависимость учёта от имён. Более поздний пользовательский фрагмент
R5 подтверждает завершение последних двух позиций, копирование при совпадающих
именах и один разворот отверстиями влево. В нём нет строки ошибки или итогового
сообщения, поэтому причину заявленного нового отказа он не устанавливает.
R6 целиком (размеры и новая компоновка) в SolidWorks ещё не проверен.

## Почему переделан основной путь

Исходный макрос действительно вставлял тела через копирование исходного вида.
Предыдущая переработка заменила этот путь созданием временного именованного
вида модели и потребовала `partModel.ActiveView`, MathUtility/MathVector,
а также сопоставления модельных рёбер с чертёжными. Ссылочная деталь может
быть загружена без окна ModelView. Эти дополнительные зависимости удалены.

Скриншот `Object variable or With block variable not set` не определяет точный
вызов: старая диагностика не сохраняла этап и писала об удалённых видах даже
при нулевом числе вставок. Конкретное место прежнего Error 91 не установлено.

## Установка

1. Скачайте **весь Drilling_Reviewed.zip**, а не только BAS. Работайте с копиями
   исходного пользовательского `.swp`, модели и чертежа. Закройте SolidWorks,
   скопируйте `integration/release` в постоянную папку Windows и один раз
   запустите `Register-Bridge.cmd` от имени администратора. Скрипт проверяет
   активацию и BuildId через `Check-Bridge.vbs`. Подробности —
   [установка компонента размеров](integration/README_RU.md).
   Для режима только видов можно явно установить `AUTO_DIMENSIONS=False`.
2. SOLIDWORKS → Инструменты → Макрос → Изменить → исходный `.swp`.
3. Удалите только стандартный модуль `InsertWeldWithHoles` и импортируйте
   новый `InsertWeldWithHoles.bas` (Windows-1251). Остальные модули сохраняйте.
   Для вставки текста `InsertWeldWithHoles.txt` вручную пропустите первую
   строку `Attribute VB_Name`: она предназначена для импорта BAS.
4. Debug → Compile, затем сохраните `.swp` в SOLIDWORKS.
5. Откройте чертёж и выберите обычный вид многотельной детали рамы.
   На листе с единственным видом выбор необязателен.
6. Запускайте **`InsertWeldWithHoles.start`**. В подтверждении и итоговом
   сообщении должен присутствовать `DRILL_COPY_VIEW_R6_DIMENSIONS_20261029`.

Нужны ссылки на SOLIDWORKS Type Library и Constant Type Library вашей версии.
Новый модуль не требует ссылки Microsoft Scripting Runtime: Dictionary
создаётся поздним связыванием.

### Нативные вспомогательные проверки

- `TestGeometry` проверяет скалярное направление нормали и выбор кандидата
  без изменения документов; это не проверка видимости/вставки.
- `TestCopyRoundTrip` на **копии чертежа** временно копирует выбранный вид,
  находит новый вид, удаляет его и проверяет восстановление набора имён
  и числа исходных видов. Чертёж не сохраняется. Этот тест не проверяет
  очистку аннотаций, фильтр тела и распознавание отверстий.

## Алгоритм

1. Включается конфигурация исходного вида, обновляется список вырезов.
   Проверяется именно `CutListFolder`; из позиции берётся первое тело с
   внутренним круглым контуром плоской грани. Между перестроениями хранятся
   имена тел, а сами `Body2` повторно получаются из исходной конфигурации.
2. Исходный вид копируется `EditCopy` и вставляется на явно выбранный текущий
   лист. Новый вид определяется разностью коллекций объектов `View` до/после вставки — без
   «последнего вида» и русских стандартных имён. При нуле или нескольких
   новых видах результат не принимается. Все обнаруженные копии учитываются
   для удаления, в том числе если Paste/перестроение завершились ошибкой.
   Уже текущий лист повторно не активируется. После необходимой активации
   проверяется фактический лист, а не только Boolean API. Проверяется также
   активный документ; два пустых пути несохранённых документов не считаются
   одним документом. Применён метод D1 из базы инженерных знаний.
3. Только у копии удаляются скопированные заметки и отображаемые размеры,
   чтобы позиции всей рамы не остались у отдельного тела. Таблицы и остальные
   виды не участвуют в этой очистке. Нативная проверка владения аннотациями
   и поведения удаления обязательна.
4. На одной копии проверяются шесть стандартных направлений через
   `ModelDoc2.ShowNamedView2` с ID Front/Back/Left/Right/Top/Bottom.
   После каждой смены повторяются фильтр одного тела, масштаб и перестроение.
   В журнал пишется фактическое `GetOrientationName`: применение числовых ID
   к выбранному виду ещё нужно проверить в установленном SOLIDWORKS. Если
   имя направления не подтверждено, повторяется вызов по русскому имени
   (как в исходнике), затем по английскому. Решение о результате всё равно
   принимается по фактической видимой грани и нормали, а не по имени команды.
5. Проверка тела учитывает разные контексты детали и чертежа: путь модели,
   конфигурация, ровно одно ненулевое тело, непустое совпадающее имя и
   единственность такого имени в `PartDoc.GetBodies2`. `IsSame` между телом
   модели и телом чертежа больше не используется.
6. Проверяются **видимые грани самого вида** в режиме без невидимых линий.
   Подходят внутренние контуры из окружности или дуг одной окружности.
   Наружная круглая граница прутка не считается отверстием. Нормаль плоской
   грани должна смотреть к наблюдателю: cos >= 0.9999. Матрица читается с
   проверками, используется скалярный расчёт без MathVector.
7. Приоритет — число круглых контуров, затем площадь грани; равенство
   сохраняет первое направление. Грань повторно получается после финального
   перестроения и поворота, а не удерживается через смены направлений.
8. Виды поворачиваются горизонтально и ставятся столбцом **от правого верхнего
   угла листа**, по фактическому GetOutline. Размеры листа читаются из Sheet,
   а нижняя граница вида рамы больше не используется. Масштаб 1:5 (`DETAIL_SCALE`), боковые поля
   20 мм, нижнее 40 мм, зазор 15 мм. При нехватке места столбец продолжается в рабочей области за листом.
   Масштаб не уменьшается; итог предупреждает о компоновке перед печатью.
   Затем каждый созданный вид отдельно выбирается объектом и обрабатывается
   AutoSizeDrilling; при окончательной компоновке резервируются размеры.
   Чертёж автоматически не сохраняется.

### Геометрия R4/R5: отверстия слева

После горизонтального поворота выбирается обращённая к наблюдателю грань
по прежнему правилу (число отверстий, затем площадь). Каждый её внутренний
круглый контур даёт один центр, даже если окружность состоит из нескольких дуг.
`MathPoint.MultiplyTransform(ModelToViewTransform)` переводит центры в координаты
листа; дополнительного умножения на масштаб нет. Если среднее X правее середины
GetOutline более чем на 0.1 мм листа, вид поворачивается в своей плоскости на 180°.
Грань, центры и габариты читаются заново; число отверстий и левая сторона проверяются.
Затем выполняется размещение. Модель не зеркалится и противоположная грань не выбирается.

Для симметричной группы поворот не нужен. Правило относится к центру группы
на выбранной грани, а не гарантирует, что каждое отверстие окажется в левой
половине детали. Разнесённые по обеим сторонам/граням отверстия требуют визуальной
проверки. `HOLES_LEFT=False` отключает только новый разворот.
Если проекция/разворот не подтверждены, восстанавливается исходный угол и
вид остаётся вставленным с явным предупреждением. Если восстановить угол
не удалось, применяется обычная обработка ошибки текущего тела.
MathUtility теперь нужен только дополнительному развороту; окно детали не требуется.

### R5: повторяющиеся имена видов

Журнал R4 показал две ссылки Type7 с одинаковыми GetName2 и GetUniqueName
`*Спереди`; проверка VBA Is не признала их одним объектом. Это опровергло
пригодность GetUniqueName как уникального ключа снимка. Сам журнал не доказывает,
что это разные логические виды, а не различные COM-обёртки одного вида.
Имена, включая GetUniqueName, в R5 используются только для диагностики.

Снимок — `Collection` живых ссылок на виды текущего листа. `SameDrawingView`
сначала проверяет VBA Is, затем положительный `ISldWorks.IsSame=swObjectSame`
в том же контексте чертежа. `swObjectUnsupported` не подтверждает совпадение:
он журналируется и не заменяется сравнением строк или геометрии. Поддержка
именно IView этим API пока нативно не установлена. До Paste два последовательных
снимка должны иметь одинаковое число объектов и взаимно сопоставляться,
а выбранный исходный вид должен входить в снимок; иначе запуск прекращается
до вставки. После Paste все старые объекты должны сохраниться до учёта дельты.
Если обёртки перестали сопоставляться, неизвестные виды автоматически не удаляются.

Выбор копируемого/поворачиваемого/удаляемого вида выполняется через
`Extension.MultiSelect2` с массивом объектов, а фактический выбранный объект
проверяется через тот же SameDrawingView. Выбор DRAWINGVIEW по имени удалён.
Выбор SHEET для вставки сохраняет рабочий путь исходного макроса.
При удалении индекс цели фиксируется до DeleteSelection2. После удаления
проверяются количество -1 и сохранение всех остальных объектов, без чтения
удалённой ссылки. При неоднозначном результате обработка останавливается.
Нативный TestCopyRoundTrip проверяет восстановление объектов, а не только имён.

### R6: размеры после создания всех видов

`AUTO_DIMENSIONS=True`: после полного прохода по телам обрабатывается только
коллекция новых успешно созданных видов. Перед каждым вызовом выбирается ровно
один ожидаемый объект, с проверкой фактического выбора. VBA вызывает отдельный
COM-адаптер `Macro.DrillingDimensions`; DLL/VSTA не запускается через неподтверждённый
RunMacro2 и не ищется другой экземпляр SolidWorks через ROT.

В адаптер напрямую подключены исходники `autosizedrilling/src/`. Добавлен строгий
`RunForIntegration`: тот же алгоритм, но отказ передаётся VBA после попытки отката
новых размеров, восстановления позиции и прежнего режима размеров. Старый
`Run(host)` по-прежнему может показывать диалог; интеграция его не использует.
Исходная DLL и прежний candidate не заменены. В COM-мосте исключён прежний VSTA-класс
с его GUID, чтобы регистрация не перезаписывала оригинальный макрос.

После размеров рамка компоновки включает геометрию и реальные позиции размерных
надписей с запасом15мм. Это не точные границы глифов. Мост сдвигает вид к правой
и верхней границам, перестраивает его и повторно сверяет SystemValue всех новых
размеров. Геометрические габариты сдвигаются вместе с видом; позиции надписей
читаются заново. VBA после успешного вызова вид больше не двигает, только
сдвигает курсор вниз по рамке оформления с зазором15мм. Проверка масштаба,
видимых рёбер, отверстий и баз остаётся алгоритмом AutoSizeDrilling; его ограничения
по пазам/косым торцам/неполным окружностям и нескольким компонентам сохраняются.

При отказе отдельного вида уже созданные виды не удаляются. Ошибки размеров
отдельно считаются и попадают в общий журнал. Если компонент не установлен
или его BuildId не совпал, виды всё равно остаются, а итог сообщает, что размеры
не выполнены. Итоговое сообщение теперь целиком записывается в журнал — включая
сводные предупреждения о выходе за поля. Поэтому следующий полный журнал позволит
отличить исключение от предупреждения компоновки.

Авторазводка относительно существующего вида рамы, штампа и чужих заметок не
выполняется: выбранное пользователем начало — правый верхний угол. При нехватке
места сохраняется разрешённая рабочая область вне листа. Размеры и их надписи
проверять перед печатью; необычный шрифт/длинный текст может превышать резерв.
Для полного повторного запуска на сохранённом чертеже сначала удалите прежние
созданные `DRILL_` виды на копии: повторный start не добавляет дубликаты.

Имена результата: `DRILL_<лист>_001`, … . Повторный запуск на листе с `DRILL_`
останавливается до копирования. Перед повторением удалите предыдущие виды
вручную или используйте копию исходного чертежа; чужие объекты не удаляются.

## Ошибки и частичный результат

Ошибка отдельного направления записывается; проверяются остальные направления.
Если тело не обработано, удаляются только его новые копии, координата размещения
восстанавливается, обработка остальных позиций продолжается. Подтверждённые
виды предыдущих позиций остаются; итог сообщает созданные и пропущенные позиции.

Если вставку не удалось учесть полностью, изменился лист или удаление
неуспешной копии не подтверждено, продолжение прекращается. Выполняется
общий откат учтённых видов с предупреждением о возможных неучтённых объектах.
Удаление проверяется по уменьшению числа видов ровно на один и сохранению
всех остальных исходных объектов; удалённый COM-объект повторно не читается; очистка остальных
учтённых объектов продолжается после отдельного отказа. Сообщение содержит
число учтённых, удалённых и оставшихся видов, включая честный ноль.

Журнал: `%TEMP%\SW_Drilling_<дата_время>.txt`, если запись доступна; также
Immediate Window редактора VBA (Ctrl+G). В нём версия, этап, тело, вид,
направление, Err.Number/Source/Description, ориентация и cos(normal).
При ошибке чтения/записи файла диагностика на экране остаётся. Журнал может
содержать названия деталей/путей из сообщения API; перед публикацией проверьте
его содержимое. Сам журнал в GitHub автоматически не отправляется.

## Таблица и позиции

По умолчанию `TABLE_TEMPLATE = ""`: создаются только виды. Для таблицы и
позиций задайте доступный путь `.sldwldtbt`. Недоступный заданный шаблон
останавливает запуск до копирования. Используется конфигурация исходного вида.
Существующие таблицы не переиспользуются и не удаляются. Если нет ни одного
готового вида, таблица этого запуска удаляется. При частичном результате она
может содержать позиции всей рамы, в том числе пропущенные тела.
Коллизии таблицы, отдельных заметок, размеров и формата листа не рассчитываются.
Позиции, количество и COM-приведение таблицы требуют нативной проверки.

## Ограничения

- Шесть стандартных направлений не гарантируют нормальный вид произвольно
  наклонённого отверстия. Такие тела пропускаются с объяснением. Временные
  именованные виды модели в этой версии не создаются.
- Пазы, сплайновые контуры и отверстия только на криволинейной грани
  не отбираются. Канал круглой трубы, карман или зенковка могут считаться
  круглым отверстием: геометрия не доказывает технологическую операцию.
- Выдаётся одна сторона тела. Отверстия по другим осям могут остаться невидимыми.
- Видимая грань может быть видна частично; наличие её круглого контура не
  доказывает полную видимость отверстия при самоэкранировании. Это отдельный
  пункт нативного визуального контроля, особенно для сложных тел/карманов.
- Удаляются только скопированные заметки и размеры. Прочие виды аннотаций
  копии могут сохраниться; их нужно проверить на реальном чертеже.
- Корректность группировки списка вырезов обязательна. Неодинаковые тела в
  одной позиции сначала нужно разделить в исходной модели.
- Новые листы не создаются, исходная модель и чертёж не сохраняются.
  Обновление списка вырезов может пометить модель изменённой. Исходная
  конфигурация восстанавливается; dirty-флаг принудительно не сбрасывается.

## Проверки выпуска

ANTLR 4.13.2 / grammars-v4 VBA 7.1: разбор актуального исходника, не старого
отчёта (`checks/grammar.json`). Метаданные Interop 32.1.0 подтверждают ключевые
сигнатуры и константы, но не поведение COM (`checks/api.json`).

`tests/test_geometry.py` проверяет извлечённые из VBA выражения: направление
нормали на шести осях и 200 углах/масштабах, выбор кандидата, идентичность
имени тела, отказ от неоднозначной вставки и продолжения после неучтённой
вставки/неполного отката, смещения по GetOutline и кодировку BAS.
Дополнительные проверки защищают порядок batch-прохода, размещение
справа/сверху, выбор одного объекта, строгую передачу отказа и кодировку.
Один статический тест защищает от возврата обязательного окна детали и

Для синтаксического разбора нужны `antlr4-python3-runtime==4.13.2` и Python
парсер, сгенерированный ANTLR 4.13.2 из `antlr/grammars-v4`, commit
`2766c2eed04f285dc763617c9459650892fcf5b9`, каталог `vba/vba7_1`:
`python3 tools/check_vba.py /путь/к/парсеру`.
Упаковка проверяет, что хеш текущего VBA совпадает с отчётом грамматики.
Она также выполняет тесты и запрещает выпуск при ошибках, пропусках или нуле тестов.
Хеши связанных C#-исходников и готовых DLL должны совпасть с checks/integration.json.
Проверки исходников требуют полного checkout с autosizedrilling, не только ZIP.
Сборки standalone/моста и23 теста Geometry выполнены; регистрация, COM-активация

Общий `check_agent_knowledge.py` дополнительно сравнивает эти файлы с неизменным
снимком до реорганизации. Он сообщает ожидаемые изменения целевого проекта;
эталон не переписывался ради прохождения проверки. В `checks/knowledge_validation.json`
раздельно сохранены код отказа, разрешённые изменения этой задачи и отсутствие
