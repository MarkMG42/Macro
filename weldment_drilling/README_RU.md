# Сверловка R7 — один модуль VBA

BUILD_ID: `DRILL_COPY_VIEW_R7_NATIVE_VBA_20261029`.

Создание видов, разворот отверстий влево, размеры и компоновка выполняются
внутри VBA SOLIDWORKS. Для запуска нужен только исходный рабочий `.swp`
с заменённым модулем `InsertWeldWithHoles`. Дополнительные DLL, регистрация,
внешние программы и права администратора не требуются. Остальные модули исходного
SWP и рабочие макросы других проектов не меняются.

**Статус:** ANTLR VBA7.1 и32 автоматические проверки расчётов/структуры/кодировки
прошли в Linux. Это не нативный Debug → Compile или запуск в SOLIDWORKS.
R7 ещё нужно испытать на копии чертежа. Исходный путь копирования/изоляции R5
частично подтверждён пользовательским журналом, но это не подтверждение новых размеров.
Проверка Defender для R7 здесь не выполнялась; отсутствие детектов не установлено.

## Установка

1. Сделайте копии исходного здорового `.swp`, модели и чертежа.
2. SOLIDWORKS → Инструменты → Макрос → Изменить → исходный `.swp`.
3. Замените только стандартный модуль `InsertWeldWithHoles`: удалите старый
   модуль и импортируйте `InsertWeldWithHoles.bas` (Windows-1251).
   Альтернатива — открыть `InsertWeldWithHoles.txt` на GitHub и вставить его
   полный текст в прежний модуль через редактор VBA. При ручной вставке
   пропустите первую строку `Attribute VB_Name`: она предназначена для импорта BAS.
4. Выполните Debug → Compile и сохраните `.swp` средствами SOLIDWORKS.
5. На копии исходного чертежа выберите обычный вид многотельной детали рамы.
   Для полного повторного запуска предварительно удалите прежние созданные
   `DRILL_` виды на этой копии; макрос не добавляет их повторно.
6. Запустите `InsertWeldWithHoles.start`. В сообщении должна быть версия R7 выше.

Все функции размеров уже включены в этот единственный BAS/TXT. Фрагменты
`source/*.vba` нужны для сопровождения исходника, отдельно импортировать их не нужно.
Нужны стандартные ссылки SOLIDWORKS Type Library и Constant Type Library вашей
версии. Scripting.Dictionary используется как встроенный объект Windows,
дополнительная ссылка Microsoft Scripting Runtime не нужна.

## Поведение

- Обновляется список вырезов исходной конфигурации. Для каждой позиции с круглыми
  внутренними контурами копируется исходный вид. Новый вид определяется по
  коллекциям объектов, а не строковым именам: GetUniqueName тоже может повторяться.
  Выбор — MultiSelect2 с проверкой фактического объекта. Перед вставкой проверяются
  два снимка, после — сохранность всех старых видов; неизвестные объекты не удаляются.
- Тело повторно находится по единственному непустому имени в исходной детали,
  изолируется в копии, проверяются модель/конфигурация/ровно одно тело. На копии
  проверяются шесть направлений. Выбираются внутренние круговые контуры плоской
  грани, обращённой к наблюдателю; приоритет число контуров, затем площадь.
- Вид становится горизонтальным. Среднее X центров отверстий выбранной грани
  сравнивается с серединой GetOutline. Если группа справа, выполняется поворот180°
  в плоскости чертежа с повторной проверкой. Симметричная группа не поворачивается.
  Правило не обещает показать отверстия со всех сторон детали одновременно.
- Столбец начинается **в правом верхнем углу листа**: правый/верхний отступ20мм,
  масштаб1:5, зазор15мм. Нижняя граница вида рамы больше не задаёт начало.
- Сначала создаются все виды. Затем каждый новый вид отдельно выбирается
  и обрабатывается `NativeDimensionView` в этом же VBA-модуле.
  После размеров рамка учитывает геометрию и позиции размерных надписей
  с запасом15мм. Вид окончательно перемещается, перестраивается, все новые
  SystemValue сверяются повторно. После успешной проверки VBA его больше не двигает.
- На успехе вид остаётся в проекционном режиме размеров. Модель и чертёж
  автоматически не сохраняются. Исходная конфигурация восстанавливается;
  обновление списка вырезов может оставить модель помеченной изменённой.

Параметры в начале модуля: `AUTO_DIMENSIONS=False` оставляет только виды,
`HOLES_LEFT=False` отключает разворот группы влево. `ALLOW_WORKSPACE_LAYOUT=True`
разрешает продолжение в рабочей области за листом при нехватке места.
Автоматическая разводка относительно существующей рамы, штампа и чужих заметок
не выполняется; перед печатью проверьте компоновку. Запас надписей не является
точным габаритом символов необычного шрифта/длинного текста.

## Логика размеров из AutoSizeDrilling

Перенесены правила `autosizedrilling/src/Geometry.cs` и `SolidWorksMacro.cs`:

- Координаты в метрах листа; допуски0.05мм и0.001мм модели умножаются на масштаб.
  ModelToViewTransform уже включает масштаб. Масштаб повторно к точкам не применяется.
- Габарит включает концы прямых и точные экстремумы круговых дуг. База должна
  лежать на истинном экстремуме; ближайшая длинная внутренняя кромка не подменяет
  наружную. Нужны четыре крайние ортогональные прямые.
- Для размеров отверстий требуется полное круговое ребро face-on с соседней
  внутренней цилиндрической гранью. Наружная дуга не выдаётся за отверстие.
  Совпадающие передний/задний ободы дедуплицируются, концентрические разные
  диаметры дают явный отказ. X/Y-позиции и группы диаметров считаются отдельно:
  два ряда по три дают6 отверстий,3 позицииX,2 позицииY и подпись6 X для общего Ø.
- Используются AddHorizontalDimension2, AddVerticalDimension2, AddDiameterDimension2,
  привязки через View.SelectEntity, центр дуги и проверка Dimension.SystemValue.
  Общий линейный Type2 допускается наряду с направленным H/V типом.
- Все новые размеры регистрируются до проверки, проверяются после создания,
  перестроения и финального размещения. При отказе удаляются только новые размеры
  этого вида и независимо восстанавливаются позиция/прежний режим. Откат best-effort;
  остаточные размеры или неудача восстановления явно сообщаются. Готовые виды остаются.

Важное различие: отбор тела допускает круговой loop из нескольких дуг, а размерение
требует полного кругового ребра по правилам AutoSizeDrilling. Если отобранное тело
не даёт ни одного поддерживаемого отверстия для размеров, R7 сообщает отказ,
а не выдаёт два общих габарита за завершённое размерение отверстий.

Не поддержаны автоматические размеры пазов, сплайнов/эллипсов, косых торцов,
нестандартно наклонённых отверстий и видов сборки/нескольких компонентов.
Признак цилиндрической стенки и выбор/привязка реальных рёбер требуют нативной
проверки, особенно на импортированных моделях. Геометрический круг не доказывает
технологическую операцию сверления. Наличие видимой грани не гарантирует отсутствие
частичного перекрытия отверстий. Чужие размеры/заметки исходного вида проверять
на сохранность: очистка копии не заменяет нативный тест владения аннотациями.

## Журнал и ошибки

Итог отдельно считает готовые виды, пропущенные позиции, размеренные/неразмеренные
виды и выход за поля. `%TEMP%\SW_Drilling_<дата_время>.txt` и Immediate Window
(Ctrl+G) содержат этап, тело, вид, направление и полное итоговое сообщение.
Длинный диалог сокращается, полный текст остаётся в журнале.
Отказ записи файла не отменяет геометрию. Журналы могут содержать пользовательские
названия/пути API; автоматически в GitHub они не отправляются.

Пользовательский фрагмент R5 показал завершение последних двух позиций и разворот,
но не содержал заявленную ошибку/итоговый диалог. Её точная причина по этому фрагменту
не установлена. Предупреждение о размещении за полями само по себе не исключение.

Таблица/позиции опциональны (`TABLE_TEMPLATE=""` — только виды и размеры).
Для таблицы нужен доступный `.sldwldtbt` и отдельная нативная проверка количества
и аннотаций. Чужие таблицы не переиспользуются/не удаляются.

## Проверки разработки

Из полного checkout, Python3 и ранее сгенерированный парсер ANTLR VBA7.1:

```sh
python3 weldment_drilling/tools/assemble_native.py
python3 weldment_drilling/tools/check_vba.py /путь/к/парсеру
python3 weldment_drilling/tools/package_release.py
cd weldment_drilling
sha256sum -c SHA256SUMS.txt
```

Assembler идемпотентен, объединяет фрагменты в один модуль. Упаковка требует
актуального grammar SHA, точного совпадения фрагментов, выполняет32 теста без
пропусков и проверяет кодировку/CRC/хеши. Новый ZIP исключает исторические
`integration/`, их DLL/PDB, Windows-скрипты установки и старые отчёты/инструменты
COM-сборки. Эти материалы R6 остаются в Git только для истории.
Дополнительные Python-инструменты — средства разработки; для запуска в SW не нужны.
Автотесты исполняют извлечённые численные выражения и проверяют структуру кода;
они не исполняют VBA/COM. ANTLR также не заменяет native Compile.
Общий checker базы знаний сравнивает с неизменным снимком до разрешённых правок;
ожидаемые изменения и отсутствие посторонних замечаний записаны отдельно
в `checks/knowledge_validation.json`, глобальное прохождение не заявляется.

## Нативная проверка на копиях в SolidWorks

1. Debug → Compile, запуск на исходной раме; источник и другие виды не изменены.
2. Совпадающие имена видов: ровно одна новая копия на позицию и только нужное тело.
3. Отверстия справа/слева/симметрично: правильная сторона к наблюдателю и группа слева.
4. Один/два ряда, разные Ø, масштабы1:1/1:10/1:100: реальные значения, центры и количества.
5. Короткая наружная/длинная внутренняя кромка швеллера: правильные базы.
6. После финального переноса: проекционный режим, SystemValue, надписи, сохранение/reopen.
7. Сплайн/косой торец/концентрические Ø/разделённые дуги: понятный отказ размеров,
   вид остаётся; уже готовые размеры и исходные объекты не удаляются.
8. Нехватка места, длинные надписи, ошибка удаления/восстановления: честная сводка
   и локальный журнал, ручная компоновка перед печатью.

## История поставки

Исходный SWP нужно сохранять через SolidWorks: ранняя source-only пересборка
контейнера не открывалась у пользователя, такой бинарник отозван.
R6 использовал отдельный COM-мост и регистрацию с правами администратора;
он не подходит под новые ограничения пользователя. Реализация и архив сохранены
в [историческом commit2f08cd5](https://github.com/MarkMG42/Macro/tree/2f08cd53a79312a428ff83db1c17586c765edbc3/weldment_drilling).
Текущий R7 запускает только встроенный VBA-код.
