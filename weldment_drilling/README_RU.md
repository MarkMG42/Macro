# Сверловка: исправленный модуль InsertWeldWithHoles

Исходник извлечён из присланного пользователем `Сверловка.swp`.
Исправлен только модуль `InsertWeldWithHoles`; `SetSizeWeldment`,
`RotateSelectedDrawingView`, `Helpers`, классы и версии объединения чертежей
V16.* не изменялись. Исходный извлечённый модуль сохранён в `original/`
в UTF-8 для сравнения, не для импорта.

**Статус: кандидат на нативную проверку.** Здесь выполнены синтаксическая,
арифметическая и API-проверки; SOLIDWORKS в Linux отсутствует.
Работоспособность на реальной раме ещё не подтверждена.

## Обновлённый файл макроса

`Сверловка_исправлено.swp` — обновлённый VBA-проект без скомпилированного
кэша. Можно открыть его в редакторе макросов SOLIDWORKS, выполнить
Debug → Compile и сохранить. Запускайте `InsertWeldWithHoles.start`.
Другие модули также содержат `start`; при назначении кнопки выберите нужный.

Контейнер пересобран Apache POI, повторно прочитан olefile/oletools:
обновлён только исходник `InsertWeldWithHoles`, остальные пять исходников
и служебные потоки SOLIDWORKS совпадают побайтно с присланным файлом.
Старый скомпилированный код всех модулей удалён, смещения исходников
сброшены. Проверка структуры **не подтверждает загрузку в SOLIDWORKS**:
первое открытие, компиляция, сохранение и запуск пока не выполнены.
Способ очистки кэша применяется в OfficePurge; его совместимость с
этим хостом VBA требует нативной проверки. Отчёт — `checks/swp.json`.

## Альтернативная установка модуля и запуск

1. Сохраните отдельную копию исходного `.swp`, модели и чертежа.
2. В SOLIDWORKS откройте копию макроса через Инструменты → Макрос → Изменить.
   Удалите **только** старый стандартный модуль `InsertWeldWithHoles` и
   импортируйте новый `InsertWeldWithHoles.bas` (Windows-1251). Не оставляйте
   два модуля с этим именем. Остальные модули и ссылки проекта сохраняйте.
   `InsertWeldWithHoles.txt` — UTF-8 исходник для просмотра. При вставке его
   в редактор вручную не вставляйте строку `Attribute VB_Name`.
3. Выполните Debug → Compile. Нужны ссылки SOLIDWORKS Type Library и
   SOLIDWORKS Constant Type Library, соответствующие установленной версии.
   Новый модуль не требует ссылки Microsoft Scripting Runtime.
4. Выполните `InsertWeldWithHoles.TestGeometry`: ожидается сообщение о семи
   проверенных направлениях. Это проверяет MathUtility, но ещё не создание видов.
5. Откройте чертёж, загрузите исходную многотельную деталь и выберите обычный
   вид рамы на нужном листе. Если на листе ровно один вид, выбор необязателен.
6. Запустите именно `InsertWeldWithHoles.start`. Другие модули тоже имеют `start`.
   Проверьте результат и только затем сохраняйте чертёж вручную.

Если обновлённый `.swp` не загрузится, используйте импорт `.bas` в копию
исходного макроса по шагам выше. Нативный скомпилированный кэш здесь
не создаётся; его создаст SOLIDWORKS/VBA после Compile и сохранения.

## Поведение

- Используется конфигурация исходного вида, а не локализованное имя конфигурации.
  Список вырезов обновляется. На каждую позицию списка создаётся один вид:
  берётся первое тело этой позиции, у которого найдена подходящая грань.
- Отверстие определяется как внутренний замкнутый контур плоской грани,
  состоящий из окружности или нескольких дуг одной окружности. Наружная
  круглая граница прутка больше не считается отверстием.
- Выбирается грань с наибольшим числом круглых внутренних контуров;
  при равенстве — с большей площадью, далее по порядку граней API.
  Её внешняя нормаль направляется к наблюдателю. Ось X ориентируется по
  длиннейшей прямой кромке грани. Поддерживаются произвольные повороты тела,
  без русских названий стандартных видов и без буфера обмена.
- После создания проверяются состав тела, направление нормали и наличие
  полного круглого контура среди видимых рёбер в режиме без невидимых линий.
  Если API не подтверждает это, запуск останавливается, а не выдаёт
  неподтверждённый вид за правильный. Затем включаются невидимые линии.
- Масштаб по умолчанию 1:5 (`DETAIL_SCALE`). Виды размещаются горизонтально
  в один столбец ниже самого нижнего существующего вида текущего листа.
  Шаг зависит от фактических габаритов после поворота и перестроения.
  Слева/справа оставляется 20 мм, снизу 40 мм, между видами 15 мм.
- Если ширины или высоты недостаточно, выдаётся причина, созданные этим
  запуском виды удаляются. Новые листы и произвольные уменьшения масштаба
  не создаются. Освободите лист либо измените `DETAIL_SCALE`.
- Виды именуются `DRILL_<имя листа>_001`, … . Если на листе уже есть `DRILL_`, запуск
  останавливается. Старые виды автоматически не удаляются.
- Автоматического сохранения нет. Временные именованные виды модели
  удаляются, исходная конфигурация и ориентация восстанавливаются.
  При ошибке удаления/восстановления показывается предупреждение.
  Обновление списка вырезов/временный именованный вид могут пометить модель
  изменённой; исходный dirty-флаг не сбрасывается принудительно.

## Таблица и позиции

В старом макросе был обязательный путь к шаблону в локальной сети автора.
Новый модуль по умолчанию создаёт **только виды**: `TABLE_TEMPLATE = ""`.
Чтобы также вставлять таблицу и позиции с количеством, задайте в этой
константе доступный путь к `.sldwldtbt`. Отсутствующий заданный шаблон
останавливает запуск до создания видов. Конфигурация таблицы берётся из вида.

Таблица вставляется в верхней левой части листа. Её коллизии с основной
надписью, существующими таблицами и аннотациями алгоритм не рассчитывает;
при включении таблицы проверьте и при необходимости переместите её вручную.
Существующие таблицы не переиспользуются. Номера и количество позиций,
интерфейс `TableAnnotation` и удаление аннотаций требуют нативной проверки.

## Ограничения геометрии

- Геометрический круглый контур не доказывает сверление: торец круглой трубы,
  цилиндрический карман и зенковка тоже могут подходить. Автоматического
  отличия штатного канала трубы от отверстия без технологического правила нет.
- Пазы, некруглые отверстия и отверстия, выходящие только на криволинейную
  грань, в этой версии не отбираются. Контуры по сплайнам также исключены.
- Один вид показывает выбранную сторону. Если отверстия расположены по
  нескольким осям, остальные могут остаться невидимыми. Для выдачи всех
  направлений нужны отдельные виды по дополнительному правилу.
- Кандидатная грань выбирается до проверки видимости; если её отверстия
  закрыты геометрией самого тела, запуск прекращается. Перебор альтернативных
  граней и частичная выдача остальных тел не выполняются.
- Проверка видимых рёбер зависит от работы API установленной версии; частично
  видимая кромка может быть возвращена как целая сущность. Визуальный контроль
  полного отверстия обязателен, особенно в карманах и сложных телах.
- Разметка не учитывает отдельные заметки, размеры и произвольную геометрию
  формата листа. Поля задаются константами, сверяйте их со своим шаблоном.
- Представитель позиции предполагает корректную группировку списка вырезов.
  Если неодинаковые тела ошибочно объединены в позицию, исправьте список.

## Проверки в этой среде

`checks/grammar.json` — новый разбор исходника ANTLR 4.13.2 / VBA 7.1.
`checks/api.json` — сигнатуры ключевых API по метаданным Interop 32.1.0
из NuGet, не нативная компиляция. Официальная справка оказалась недоступна
через прокси (HTTP 403). `tests/test_geometry.py` выполняет выражения
векторных функций и индексы матрицы, извлечённые из выпускаемого VBA:
6 осевых направлений, 200 случайных направлений, вырожденные/параллельные
оси, правый базис, сохранение длин и смещения по габаритам вида.
Этот тест не исполняет VBA и не эмулирует SOLIDWORKS/COM.

Воспроизведение упаковки и арифметических проверок (Python 3.12, stdlib):

```sh
cd /workspace/Macro/weldment_drilling
python3 tools/package_release.py
python3 -m unittest discover -s tests -v
sha256sum -c SHA256SUMS.txt
```

Для повторного синтаксического разбора нужен Python runtime
`antlr4-python3-runtime==4.13.2` и Python-парсер, сгенерированный ANTLR 4.13.2
из `vba/vba7_1` репозитория `antlr/grammars-v4` на коммите
`2766c2eed04f285dc763617c9459650892fcf5b9`:

```sh
python3 tools/check_vba.py /путь/к/сгенерированному/парсеру
```

Проверка выпуска останавливается, если хеш исходника не соответствует отчёту
синтаксического разбора; готовый отчёт нельзя использовать для изменённого VBA.

Пересборка source-only `.swp` выполняется `tools/build_swp.py` с исходным
вложением пользователя и каталогом проверенных зависимостей Apache POI
(Java 17+, oletools 0.60.2, olefile 0.47). Версии, адреса Maven и контрольные
суммы библиотек — в `checks/swp_dependencies.json`. Скрипт принимает только
исходный файл с ожидаемым SHA256 и не перезаписывает его.

```sh
python3 tools/build_swp.py /путь/к/исходной/Сверловка.swp /каталог/poi-jars
python3 tools/package_release.py
```

## Обязательная проверка в SOLIDWORKS (не выполнена)

На копиях документов проверьте следующие случаи; записывайте версию
SOLIDWORKS, конфигурацию, число ожидаемых позиций и фактических видов.

| Сценарий | Ожидается |
| --- | --- |
| Нет документа / деталь вместо чертежа / несколько видов без выбора | Понятная ошибка без изменения чертежа |
| Нет отверстий / пустые папки списка | Сообщение об отсутствии подходящих тел, без ошибки массива |
| Одна позиция и несколько одинаковых тел | Один вид этой позиции; без лишнего `Nothing` |
| Сплошной круглый пруток | Наружная окружность не считается отверстием |
| Сквозное и глухое отверстия с шести сторон, повёрнутое тело | Отверстие обращено к наблюдателю, в виде только выбранное тело |
| Окружность разбита на две/несколько дуг | Отверстие найдено, посторонние дуги не принимаются |
| Труба, паз, сплайновый контур, карман | Поведение соответствует ограничениям выше |
| Другая конфигурация в модели и в виде | Выбор тел соответствует виду; исходная конфигурация восстановлена |
| Сохранить/закрыть/открыть копию готового чертежа | Ориентация и фильтр тела сохранены после удаления временного именованного вида |
| Крупное тело, мало места, другая ширина листа | Нет наложений/выхода за лист; при ошибке весь результат текущего запуска удалён |
| Повторный запуск на том же листе | Нет дубликатов; явное сообщение о `DRILL_` |
| TABLE_TEMPLATE задан / неверен | Верные позиции и количества / ранняя ошибка без новых видов |
| Искусственная ошибка после создания 1–2 видов | Созданные виды и их позиции удалены, старые объекты остались |
| Временный вид нельзя удалить / модель нельзя восстановить | Явное предупреждение; никакого автосохранения |

Проверить также, что шаблон таблицы доступен, его COM-интерфейс приводится
к `TableAnnotation`, заметки принадлежат нужным видам, а после любого исхода
чертёж активен и графика обновляется. Ускорение через выключение графики и
дерева из старого макроса удалено: оставлять их выключенными теперь нечему.
