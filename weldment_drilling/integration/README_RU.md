# Вызов AutoSizeDrilling из VBA

Этот адаптер запускает исходный алгоритм из `autosizedrilling/src/` на одном
явно выбранном созданном виде. Имена видов не служат идентификаторами.
Он не является VSTA-макросом и не запускается через «Макрос → Выполнить».

**Статус:** мост и standalone собраны для .NET Framework 4.8/x64 без предупреждений,
23 теста геометрии прошли; метаданные COM проверены. Регистрация,
COM-активация и работа с SOLIDWORKS требуют нативной проверки в Windows.
Исходная DLL и бинарник `autosizedrilling/candidate` не заменяются.

## Установка в Windows

1. Закройте SOLIDWORKS. Распакуйте весь каталог `release` в постоянную папку,
   например `C:\SolidWorksMacros\DrillingDimensions`. В ней должны находиться
   `Macro.DrillingDimensionsBridge.dll`, обе `SolidWorks.Interop.*.dll`
   и `Register-Bridge.cmd`/`Unregister-Bridge.cmd`.
2. Запустите `Register-Bridge.cmd` **от имени администратора**. Скрипт использует
   64-разрядный .NET Framework RegAsm и регистрирует только новый мост
   `Macro.DrillingDimensions`; исходная `AutoSizeDrilling.dll` не регистрируется.
   `/codebase` связывает регистрацию с текущей постоянной папкой: после установки
   файлы нельзя переносить. Предупреждение RegAsm о неподписанной сборке при
   `/codebase` само по себе не доказывает успешную активацию; проверьте результат
   установки и контрольный вызов ниже. В конце скрипт запускает
   `Check-Bridge.vbs` через64-разрядный cscript для проверки активации/версии. Защиту Windows отключать не требуется.
3. Откройте SOLIDWORKS и импортируйте актуальный BAS сверловки из родительского
   каталога выпуска. Встроенная проверка должна прочитать `BuildId` адаптера.
4. При обновлении закройте SOLIDWORKS, запустите старый `Unregister-Bridge.cmd`,
   замените файлы выпуска и повторите регистрацию. Для удаления сначала выполните
   отмену регистрации, затем удаляйте файлы.

Проверка активации в Immediate Window редактора VBA SOLIDWORKS:

```vb
? CreateObject("Macro.DrillingDimensions").BuildId
```

Ожидается `DRILLING_DIMENSIONS_BRIDGE_R2_20261029`. Это проверяет только загрузку
адаптера; не геометрию и не постановку размеров.

## Контракт интеграции

- `BuildId`: строка версии адаптера для согласования с VBA.
- `ProcessSelectedView(application, expectedView, targetRight, targetTop)`: два COM-объекта
  и координаты правой/верхней границ в метрах листа. Передаются
  текущий `Application.SldWorks` и ожидаемый `SldWorks.View` из коллекции новых
  видов. Перед вызовом выбран ровно этот один вид. Другое окно SOLIDWORKS через
  ROT не ищется; ошибка не скрывается диалогом.
- Мост создаёт размеры, перемещает вид вместе с оформлением к targetRight/targetTop,
  перестраивает, повторно проверяет SystemValue всех созданных размеров и границы
  компоновки. При ошибке пытается вернуть прежнюю позицию, режим и удалить новые
  размеры. После успеха VBA повторно вид не перемещает.
- Результат: Variant с `Double(0..4)` — число проверенных размеров, left, bottom,
  right, top в метрах листа. Габариты консервативны: позиции размерных надписей
  с запасом, а не точные границы нарисованных символов. Компоновку перед печатью
  нужно визуально проверить.
- Ошибка алгоритма передаётся вызывающему VBA после попытки удалить только новые размеры
  и восстановить прежний режим размеров текущего вида. Неудача отката включается
  в ошибку; исходные и успешно обработанные виды не следует удалять из-за неё.
  Проверка возвращённого результата адаптером не является отдельной транзакцией:
  при некорректном результате уже созданные размеры не удаляются самим адаптером.
- На успехе выбранный вид остаётся в режиме проекционных размеров, как предусмотрено
  AutoSizeDrilling. Документы автоматически не сохраняются.

Сборка напрямую подключает `SolidWorksMacro.cs`, `Geometry.cs`, `DiagnosticLog.cs`.
Символ `DRILLING_BATCH` исключает прежний VSTA-класс с его историческим GUID,
поэтому регистрация моста не перезаписывает класс оригинального макроса.
Assembly-wide `ComVisible(false)` и явный IDispatch открывают только новый адаптер.
Поддержка сравнения IView через `IsSame` должна быть проверена в установленном
SOLIDWORKS; `swObjectUnsupported` не принимается за положительное совпадение.

## Сборка и проверка

Из корня репозитория, с установленным .NET SDK:

```sh
python3 weldment_drilling/tools/check_integration.py /путь/к/dotnet /tmp/drilling-validation
```

Нужны Python dnfile и полный checkout. Скрипт реально выполняет три сборки,
запускает23 Geometry-теста, проверяет x64/COM-метаданные, копирует готовые DLL
в release и записывает хеши в checks/integration.json. Команда dotnet run
в SDK8 с --artifacts-path ищет executable по старому пути; тестовый DLL
поэтому запускается явно через dotnet из каталога artifacts.

Требуется NuGet-пакет `Microsoft.NETFramework.ReferenceAssemblies` версии1.0.3.
Ссылки на предоставленные interop берутся из `autosizedrilling/` и копируются
рядом с адаптером. Не регистрировать сборку или исходную DLL в Linux.
Перед выпуском проверить метаданные COM и отсутствие старого VSTA-класса.

Нативные сценарии на копии чертежа: активация; один выбранный вид; несколько
созданных видов последовательно; одинаковые имена; два процесса SOLIDWORKS;
неподдерживаемое отверстие с откатом размеров текущего вида; сохранность размеров
прежних видов; размещение справа/сверху с резервом под надписи; повторный запуск.
Применимость геометрии и её ограничения остаются прежними — см. `autosizedrilling/CHANGES.md`.
