# V16.20 — ссылки на компоненты в заметках разрезов

BUILD_ID: MERGE_DRAWINGS_V16_20_SECTION_COMPONENT_LINK_20261028

Обновление: заменить только стандартный модуль текстом MERGE_DRAWINGS_V16_20.txt,
выполнить Debug → Compile и сохранить .swp. Форму frmDrawingOrder не менять.
Альтернатива — удалить старый стандартный модуль и импортировать MergeDrawingsV16_20.bas
(Windows-1251). Не оставлять два main. При первой установке создать стандартный модуль
и пустую UserForm с (Name)=frmDrawingOrder, вставить FORM_CODE.txt в её код.

## Что установлено

В исходнике обе заметки разрезов показывают наименование, хотя используют одинаковую
служебную ссылку SectionAssembly. После переноса геометрические привязки сохранены,
но выражение ссылается на старый служебный контекст; GetText возвращает пустую строку.
В последнем журнале обработка остановилась на источнике «…из со» до добавления рамы.
Несоответствие между компонентом в строке и компонентом выноски есть уже в исходнике.
Исходную служебную строку нельзя использовать как надёжный адрес экземпляра.

## Изменение

Если исходный текст непустой, а после установки ссылки SectionAssembly текст пуст,
V16.20 пытается восстановить $COMP из фактического дерева RootDrawingComponent вида
результата. Поддерживается ровно одна геометрическая привязка и одно выражение $COMP.
Компонент ищется по точному пути модели, конфигурации и полному имени экземпляра,
полученным из сохранённой привязки выноски. Должно быть ровно одно совпадение.
Адрес строится по цепочке экземпляров дерева вида, без выдуманного имени скрытого вида
и без замены текста постоянной строкой. Свойство «Наименование» остаётся живой ссылкой.

Восстановленная ссылка записывается в ожидаемый снимок для последующих проверок.
Строгие проверки привязок, количества заметок, выражения, слоя, видимости и исходного
текста остаются. Неподдерживаемые/неоднозначные случаи и пустой текст после перестроения
останавливают обработку. В журнале добавлено SECTION NOTE rebuilt с выражением и текстом.

Перенос разрезов, сортировка, источник свойств листов и ускоренное сохранение V16.18
не изменены. Результат — новый MERGED рядом с основным чертежом; оригиналы защищены.
SOURCE-копии нужны только для семейств видов, распределённых между листами.
По умолчанию VERIFY_AFTER_SAVE=False: проверяется открытый документ после Save3,
повторное открытие не выполняется. Для дополнительной проверки можно включить True.
После первого запуска проверьте заметки и после ручного повторного открытия результата.
При FAILED сохранённый MERGED может содержать частичный, непроверенный результат.

Грамматика VBA, API interop и сборка архива проверены в облаке. Нативная компиляция
VBA и SOLIDWORKS здесь недоступны: построение адресов по дереву и отображение заметок
нужно подтвердить повторным запуском на исходных чертежах.
