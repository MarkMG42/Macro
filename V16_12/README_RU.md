# V16.12 — проверка фактического источника свойств

BUILD_ID: MERGE_DRAWINGS_V16_12_PROPERTY_SEMANTICS_20261027

## Обновление после V16.11

Форма frmDrawingOrder и FORM_CODE.txt не изменились. Если V16.11 уже установлена,
заменить ТОЛЬКО код стандартного модуля содержимым MERGE_DRAWINGS_V16_12.txt,
выполнить Debug → Compile, сохранить .swp и запустить main. Форму пересоздавать
или вставлять код повторно не требуется. При импорте BAS удалить предыдущий
стандартный модуль: не оставлять две версии main и OrderPickFiles/OrderFolderFiles.

Для первой установки: создать .swp, вставить основной модуль, добавить пустую
UserForm с (Name)=frmDrawingOrder и вставить FORM_CODE.txt в код этой формы.
Кнопки создаются внутри VBA. В комплекте нет HTA и запуска внешних процессов.

## Что показал журнал V16.11

PROPERTY MODE ... inherited=True; requested=True. При этом проверка требовала
имя явного локального вида Чертежный вид4. Установка режима наследования и такое
ожидание противоречили друг другу. Это ошибка кода проверки, а не доказанный
отказ SOLIDWORKS. Изменять один текст метки на другой и считать всё исправным
тоже недостаточно: после объединения документ-источник настроек уже другой.

V16.12:
- Не преобразует метку Default/По умолчанию в локальный вид при SameCustomProp=True.
- Считывает настройки документа swDrawingSheetsMatchCustomPropVals и
  swDrawingSheetCustomPropSheetNo через IModelDocExtension. Номер листа настроек
  трактуется как номер 1..N; вне диапазона — диагностическая остановка, не угадывание.
- Определяет действительный вид-источник: при действующем наследовании берётся
  лист из настроек документа, иначе текущий лист; явное имя вида имеет приоритет,
  для известных системных меток используется первый вид выбранного листа.
  Нераспознанные режимы останавливают выполнение.
- Фиксирует модель и конфигурацию этого вида в исходном снимке. После переноса,
  сохранения и повторного открытия сравнивает их с ожидаемыми.
- Равенство флагов режима проверяется всегда. Равенство строковых имён вида —
  только в локальном режиме, где это действительное имя, а не подпись режима.

Новые строки PROPERTY DOCUMENT и PROPERTY SOURCE CHECK содержат настройки,
ожидаемую/фактическую модель и конфигурацию. Если наследование в объединённом
документе даст другую модель или конфигурацию, макрос остановится: скрывать
изменение штампов ради SUCCESS нельзя. Такое несовпадение может потребовать
отдельного переназначения источника свойств; это не выполняется наугад.

Все проверки геометрии, видов, родителей, оформления, сохранения и PDF сохранены.
Для текущего комплекта ожидаются 5 листов и оба связанных разреза. После SUCCESS
сравнить штампы с исходниками. Если снова FAILED, прислать полный merge.log.
Использовать исходные сохранённые чертежи, не WORK_TARGET/SOURCE прошлого запуска.

## Проверки и ограничения

Проверены грамматика полного стандартного модуля, эквивалентность BAS/TXT,
лимиты строк, уникальность процедур, неизменность формы и PDF-экспорта,
целостность ZIP/SHA-256. GetUserPreferenceToggle/GetUserPreferenceInteger
с двумя аргументами и имена настроек сверены с interop/swconst 32.1.0.
Нативная компиляция VBA, исполнение новых API на SOLIDWORKS 33.4.1, проверка
полей штампов и Defender здесь не выполнялись. Если защита блокирует новую
реализацию, обходить её не нужно. Это исходники, не готовый бинарный .swp.
