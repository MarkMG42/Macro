# V16.1: проверка активации листа

BUILD_ID: MERGE_DRAWINGS_V16_1_SHEET_ACTIVATION_20261027

Ошибка пользователя возникает в CaptureDrawing до переноса видов. V16 проверяла
только Boolean ActivateSheet. Из журнала нельзя установить, был ли Лист1 уже активен.

Исправление: единый EnsureSheetActive для чтения, переноса, копирования,
перестроения и восстановления листов. Уже текущий лист не активируется повторно.
При переключении проверяется GetCurrentSheet.GetName: False с правильным текущим
листом допускается, True с неправильным листом вызывает остановку. Перед
переключением выполняется EditSheet. Нет повторов, DoEvents и отключения проверок
связей видов. Добавлена диагностика SHEET CURRENT / SHEET ACTIVATE и этапов CLONE.

Установка: полностью заменить стандартный модуль текстом MERGE_DRAWINGS_V16.txt
(UTF-8) либо импортировать MergeDrawingsV16.bas (Windows-1251) вместо старого
модуля. Не оставлять оба модуля. Имена файлов оставлены для совместимости.
Выполнить Debug → Compile и запустить main. Проверить новый BUILD_ID в merge.log.

Проверка на Linux: BAS/TXT эквивалентны, лимиты строк/продолжений соблюдены,
нет дублирующихся процедур, все обязательные активации используют общий helper,
экспорт PDF совпадает с исходным V16. Сборка выполнена build_release.py.
Компиляция VBA, выполнение COM и реальный CAD-тест не выполнялись.
Отчёты checks и остальные markdown из исходного V16 — исторические данные,
они не доказывают проверку V16.1. check_release.py/check_api.py требуют внешних
материалов, отсутствующих в архиве, и не выполнялись для этой версии.

Повторить запуск с теми же чертежами. Ожидаемый итог из исходного описания:
SUCCESS, 9 листов, оба разреза и их связи сохранены. Если снова FAILED, передать
полный merge.log из нового runs, включая CLONE и SHEET. Исходные CAD-файлы
макрос не перезаписывает. Успех этой корректировки требует проверки в SOLIDWORKS.
