# Внутренние адреса заметок разрезов

Диагностика для ошибки V16.20; макрос объединения не изменяется.

1. В отдельном макросе аудита заменить стандартный модуль текстом AuditNoteContext.txt.
   Выполнить Debug → Compile и сохранить .swp. UserForm не нужна.
2. Открыть исходный чертёж «…из со», сделать его активным, запустить main аудита.
3. Сделать активным сохранённый MERGED и запустить тот же аудит ещё раз.
4. Передать два созданных NOTES_CONTEXT_….tsv. Повторять объединение не нужно.

При первой установке создать отдельный .swp со стандартным модулем и этим кодом.
Вариант .bas предназначен для импорта вместо вставки текста; не оставлять два main.

Аудит только читает объекты и создаёт новый TSV рядом с активным чертежом.
Заметки не редактирует, чертежи не сохраняет и не перестраивает. Переключает листы
для чтения и возвращает исходный активный лист. Отчёты содержат личные пути.
Три новые колонки содержат Name/GetName2/GetUniqueName вида, корневой
DrawingComponent.Name и GetSelectByIDString компонентов. Ошибка отдельного
дополнительного чтения записывается в соответствующую ячейку как ERROR.

V16.20 построила ссылку по Component.Name2 и View.GetName2; в полученном журнале
она записалась, но текст остался пустым после перестроения. Сам факт успешного
присваивания PropertyLinkedText не подтверждает разрешимость ссылки. До получения
нативных адресов очередная замена строк не считается подтверждённым исправлением.

Проверены грамматика и наличие методов в interop. Нативная компиляция VBA и запуск
SOLIDWORKS в облаке недоступны.
