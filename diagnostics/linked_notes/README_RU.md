# Проверка заметок «Связать со свойством → Наименование»

Это отдельный диагностический макрос, не новая версия объединения и не
исправление привязок. Он читает заметки в активном чертеже через GetNotes
служебного вида листа и обычных видов. Для каждой заметки выводятся:

- имя и текст, который сейчас возвращает Note.GetText;
- исходная строка Note.PropertyLinkedText с кодом связи со свойством;
- имя аннотации, состояние видимости, слой и его видимость/печать;
- положение, число/типы прикреплённых объектов;
- имя, путь к модели и конфигурация компонента выноски, если API их возвращает;
- отметка contains_naimenovanie и состояние чтения read_status.

Это позволяет проверить сообщение об исчезновении самого объекта заметки,
а также случаи, когда объект остался, но его связь/отображение изменились.
Само совпадение количества аннотаций в макросе объединения недостаточно:
оно не удостоверяет наличие конкретной заметки с нужной ссылкой и значением.
Без исходника и результата именно проблемного случая причина не установлена.

## Как использовать

1. Рабочий .swp объединения не изменять. В SOLIDWORKS создать отдельный новый
   макрос NotesAudit.swp. В стандартном модуле заменить код всем текстом
   AuditLinkedNotes.txt. Альтернатива — импортировать AuditLinkedNotes.bas
   вместо пустого стандартного модуля. Форма не нужна.
2. В References должны быть библиотеки SOLIDWORKS и swconst. Выполнить
   Debug → Compile и сохранить новый диагностический .swp.
3. Открыть исходный чертёж, где нужная заметка видна, и сделать его активным.
   Запустить main диагностического макроса. Рядом с чертежом создастся
   NOTES_AUDIT_<имя чертежа>_<дата/время>.tsv. Путь покажет сообщение.
4. Открыть объединённый чертёж, где заметка пропала, сделать его активным
   и запустить этот же диагностический main ещё раз.
5. Передать оба TSV и указать исходный текст нужной заметки/лист.
   Если в отчётах есть лишняя конфиденциальная информация, можно передать
   строки нужной заметки, заголовок и строки предполагаемого владельца.

Отчёты содержат тексты заметок, имена/пути моделей и компонентов: не публиковать
их в открытом репозитории. Сам макрос не отправляет отчёты по сети.

## Что он меняет

Создаёт только отдельный новый TSV без перезаписи существующих файлов. Для чтения
переключает листы и пытается вернуть исходный активный лист. Не вызывает Save3,
SaveAs, перестроение, удаление, Cut/Paste, установку текста или перепривязку
выносок. Если в папку чертежа нельзя писать, сообщит ошибку. Никаких HTA,
внешних процессов, прав администратора или дополнительной формы не требуется.

## Как читать ограничения

read_status=OK означает, что основные поля прочитаны, а не что ссылка исправна.
В attached_components может быть ATTACHMENT_READ_ERROR, NULL_ATTACHMENT или
NO_COMPONENT_RETURNED. Эти значения не доказывают удаление/потерю привязки:
для некоторых типов геометрии компонент не удалось получить данным API.
В таком случае нужно учитывать и код ссылки, и владельца заметки, и другие поля.
not-resolved в столбцах слоя не означает «слой скрыт».

ERROR в read_status или сообщение «Проверка не завершена» означает неполные
данные; по ним нельзя объявлять заметку потерянной. Форматы листа/заметки,
недоступные через GetNotes, и все варианты сложных аннотаций не заявлены как
полностью покрытые. Для текущего случая нужны заметки на видах со ссылками
на свойства выбранных компонентов, а не только штампы.

Грамматика VBA и сигнатуры использованных API сверяются в checks.json и
api_checks.json. Нативная компиляция/работа в Windows/SOLIDWORKS и антивирусная
проверка здесь не выполнялись. Это диагностический исходник, не готовый .swp.
При срабатывании защиты не обходить блокировку.
