# V16.9 — стандартные диалоги VBA

BUILD_ID: MERGE_DRAWINGS_V16_9_NATIVE_DIALOGS_20261027

Удалены HTML/JavaScript-окно сортировки, создание HTA и запуск внешнего процесса.
В новой поставке нет прежних архивов и исходников старого окна. Пользовательский
интерфейс использует VBA.InputBox, MsgBox и имеющийся стандартный файловый диалог
Windows через comdlg32.dll. Установка дополнительных компонентов и повышение
прав не требуются. Сам макрос работает внутри SOLIDWORKS через его COM API и
использует FileSystemObject для локальных файлов и Dictionary для списков.
Это не отказ от COM вообще: удалён сценарий запуска отдельного скриптового окна.

Порядок задаётся текстовыми командами, без перетаскивания:
- OK — принять текущий список.
- M 3 1 — переместить источник №3 на место №1.
- R 2 — убрать источник №2.
- V 2 — показать полный путь источника №2.
- A — добавить файлы стандартным диалогом.
- F — добавить чертежи из папки, путь вводится отдельным окном.
- N / P — следующая / предыдущая страница списка (по 5 строк).
- Отмена или пустой ввод — отменить объединение.

Команды вводятся латинскими буквами. Номера глобальные для всего списка.
Основной чертёж всегда первый и в этом списке не редактируется. Повторные пути,
основной документ, временные ~$ и расширения кроме .slddrw исключаются.
Для длинных путей используйте A; окно ввода пути F имеет ограничения InputBox.
В журнал записываются принятый порядок и полные пути. Временные файлы окна
сортировки больше не создаются. Само объединение создаёт рабочие копии и журнал
в runs, как раньше. CAD-алгоритм V16.8 не изменён, включая ещё не подтверждённое
нативным запуском исправление источника свойств листа.

## Установка

1. Использовать только этот новый архив, не полный архив истории репозитория.
2. Открыть существующий .swp в редакторе VBA SOLIDWORKS и полностью заменить
   стандартный модуль содержимым MERGE_DRAWINGS_V16_9.txt (UTF-8).
   Альтернатива: удалить старый модуль и импортировать MergeDrawingsV16_9.bas
   (Windows-1251) вместо него. Не оставлять старую и новую версии вместе.
3. Debug → Compile, сохранить .swp, запустить main.
4. Проверить BUILD_ID, журнал и итоговый STATUS. Для текущего комплекта ожидаются
   5 листов, оба связанных разреза, сохранённый итоговый SLDDRW и PDF.
   Сравнить заполнение штампов с исходными документами.

Если Defender блокирует новый файл, не отключать защиту и не добавлять исключение.
Устранён конкретный механизм внешнего скриптового окна; это не доказательство
ложного срабатывания старой версии и не гарантия прохождения проверки Defender.
Антивирусного заключения для нового файла здесь нет. При новом срабатывании
нужно сохранить доступный текст предупреждения и обратиться к администратору.

## Проверки и воспроизводимость

python3 tools/build_release.py собирает автономные BAS/TXT из tools/*.vba.
python3 tools/package_release.py пересобирает, проверяет и упаковывает комплект.
Не нужны скачивания, внешние библиотеки Python, исследовательские DLL или доступ
к интернету. Скрипты не запускаются макросом и не требуются на Windows для работы.

Выполнены эквивалентность BAS/TXT, лимиты строк/продолжений, уникальность процедур,
сверка неизменности CAD-ядра с V16.8 (кроме BUILD_ID), отсутствие прежнего скриптового
окна/запуска процессов в полном модуле, целостность ZIP/SHA-256. Отдельная грамматика
VBA проверяется ANTLR; результат записан в checks/grammar.json после завершения.
Это не компиляция редактором VBA, не выполнение COM/SOLIDWORKS, не проверка
диалогов на Windows и не антивирусное сканирование.
