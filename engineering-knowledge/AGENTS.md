# SolidWorks: постоянные инженерные знания

Проект автоматизирует SolidWorks через VBA/COM. Основная целевая версия для новых
задач — SolidWorks 2025. Исторические испытания в чате: 33.4.1 (SW 2025).
Имеется также C#/.NET/VSTA-материал AutoSizeDrilling; общая база охватывает его
через `dimensions.md`, сохраняя различие исходной DLL и непроверенного кандидата.
Отчёты interop 32.1.0 сами по себе не доказывают совместимость с 2025.

## Перед работой

1. Прочитай `engineering-knowledge/topics/README.md` — небольшой каталог, затем только
   файлы нужных областей и относящиеся к решению источники. Не загружай все версии.
2. Определи применимость: версия SW, тип документа, зависимости видов, способ
   привязки заметок, режим сохранения. Различай подтверждение пользователя,
   реальный журнал SW, автоматическую проверку и гипотезу.
3. За основу переноса разрезов/заметок бери подтверждённую V16.21;
   V16.22 меняет запись основного файла и пока не подтверждена нативным запуском.
   Не переписывай зафиксированные рабочие версии и их архивы.

## Координация профильных агентов

Простую задачу выполняй сам. Для существенных независимых инженерных вопросов
самостоятельно выбирай специализации из каталога. Для межобластной задачи
привлекай нужные профили и передавай им общие ограничения/контракт данных.
Пользователь разрешил такой способ работы; учитывай ограничения текущего клиента.

Для любой дальнейшей инженерной работы над `weldment_drilling/` — анализа ошибок,
изменения алгоритма или кода, оптимизации, подготовки выпуска — **обязательно
подключай существующих профильных подагентов до правки макроса**. Сначала определи
затронутые области; для видов и таблиц используй `sw_drawings`, для отверстий и
размеров — `sw_dimensions`, для VBA/COM и поставки — `sw_vba_com`. Если задача
затрагивает несколько областей, привлеки каждый соответствующий профиль и сведи
их независимые выводы перед реализацией. Не создавай новую специализацию, пока
подходит существующая. Простые ответы на вопросы и правка самой документации
не требуют отдельного запуска агентов. Если инструмент подагентов недоступен,
явно сообщи об этом и выполни профильную проверку самостоятельно.

Если клиент поддерживает именованные роли, используй `.codex/config.toml`.
Если spawn-инструмент не принимает роль, прочитай `developer_instructions` нужного
`engineering-knowledge/agents/*.toml` и передай их вместе с конкретной задачей в сообщение агенту.
Без инструментов подагентов выполняй тот же разбор самостоятельно, не имитируя запуск.
Модель/права наследуются от текущей сессии; не повышай их через конфиги.

Назначай непересекающиеся файлы записи. По умолчанию профильные агенты исследуют
только чтением и возвращают: вывод, статус, доказательство (файл/функция), условия,
риски, предлагаемое обновление знаний. Координатор объединяет результаты и
редактирует общую базу. Не запускай рекурсивные команды агентов без необходимости.
Новый профиль создавай только для реальной области, не покрытой текущими;
обнови каталог, один файл знаний и конфигурацию, не плодя пустые специализации.

## После значимой задачи

Автоматически оцени новые API-приёмы, ограничения и причины ошибок. Обнови
соответствующую существующую запись по шаблону каталога: задача, API, алгоритм,
реализация, сбои, ограничения, проверка, связи. Новый результат, опровергающий
старый, меняет текущую рекомендацию, но сохраняет полезное объяснение ошибки.
Записывай дату/версию/среду и источник подтверждения. Повышай статус только по
новым доказательствам. Не сохраняй мелочи, переписки, длинные логи и секретные пути.
В итоговом ответе укажи существенное обновление знаний или причину его отсутствия.

## Проверка и границы

Не выдумывай методы API. Читай реализацию и проверяй сигнатуры в документации/
interop; следуй `engineering-knowledge/topics/vba-com.md`. Статические отчёты не равны Debug → Compile и запуску
SolidWorks. Сохраняй строгость проверок связей, модели/конфигурации и заметок.
Не обходи Defender. Не публикуй исходные пользовательские журналы/чертежи.
Git push требует явного разрешения пользователя; первоначальная настройка базы
его не разрешает. Не меняй рабочие макросы ради обслуживания документации.

## Размещение проектов (уточнение пользователя 29.10.2026)

В `drawingmerger/` собраны все папки версий V16_9–V16_22, ZIP-выпуски и паспорта
объединения. Основной рабочий вариант — V16.21; перенос остальных версий не
повышает их статус. Не удалять исторические варианты на основании одного номера.
`diagnostics/`, `docs/agent-knowledge/`, `weldment_drilling/` по прямому указанию
пользователя остаются в корне; текущая реорганизация не меняет их содержимое.
Знания и инструкции этой системы — в engineering-knowledge, корневые AGENTS.md
и .codex/config.toml остаются точками входа. Не путать защищённые существующие
исследования docs/agent-knowledge с новым каталогом engineering-knowledge/topics.
