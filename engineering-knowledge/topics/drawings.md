# Листы и зависимые виды

## D1. Надёжная активация и снимки

Задача: операции должны выполняться с нужным документом/листом, включая кириллицу
и одинаковые заголовки документов. Статус: входит в подтверждённую пользователем
V21; ранние ошибки активации описаны в доступной истории. Реализация:
[merge_core.vba](../../drawingmerger/V16_21/tools/merge_core.vba), `CaptureDrawing`,
`EnsureSheetActive`, `RequireActive`, `EnsureWorkingDirectory`.

- Порядок листов брать из `DrawingDoc.GetSheetNames`; для каждого читать
  `GetCurrentSheet`, виды и `GetBaseView`, в конце возвращать исходный лист.
- Если лист уже текущий, не вызывать повторно `ActivateSheet`. После вызова
  проверять фактический `GetCurrentSheet.GetName`, а не один Boolean API.
- После `ActivateDoc3` сверять полный нормализованный `GetPathName` ActiveDoc.
- Перед открытием рабочих копий устанавливать проверенный каталог поиска моделей;
  незаданный каталог вызывал остановку. Объекты документа и активный документ —
  разные понятия; сверять фактическое состояние перед вставкой.

Ограничение: не привязывать порядок к индексам массива GetViews и не считать
сервисный вид листа обычным модельным видом. Применимо к пакетному экспорту,
обходу аннотаций и созданию новых видов.

## D2. Перенос семейств разрезов между листами

Задача: сохранить native parent-child связи, а не только похожее изображение.
Статус: Подтверждено пользователем для V15/V21 на его комплектах;
не универсальный тест всех типов видов. Реализация того же
[merge_core.vba](../../drawingmerger/V16_21/tools/merge_core.vba): `DependencyOrder`,
`AppendDrawing`, `MoveView`, `SelectViewForMove`, `CopyWholeSheet`,
`MapCopiedSheet`, `SameViewFingerprint`, `RestoreView`, `VerifyDrawing`;
[source_properties.vba](../../drawingmerger/V16_21/tools/source_properties.vba): `PrepareSource`.

Алгоритм:

1. Снимок графа `View.GetBaseView`, проверка родителей/циклов, порядок parent-first.
2. Для межлистового семейства создать приватную редактируемую SOURCE-копию.
   Собрать зависимые виды на листе корня native `EditCut`/`Paste`, сохраняя масштаб.
   Для уже локальных семейств читать оригинал без лишней копии.
3. `EditCopy` + `DrawingDoc.PasteSheet` переносит целый native-лист; копировать
   также временно опустевшие исходные листы. Проверить ровно один новый лист.
4. Сопоставить переименованные виды по однозначному fingerprint модели,
   конфигурации, геометрических параметров и уже сопоставленному родителю.
5. Разнести потомков обратно leaves-first; вернуть масштаб/позицию/режимы
   parent-first. После переносов проверить структуру и итоговый снимок.

`MoveView` использует `MultiSelect2` с проверкой SelectionManager, затем EditCut,
активацию целевого листа, EditSheet, очистку выделения и `Paste` без выделенного
листа назначения. Иначе вставка могла идти не в ожидаемый контекст.
Повторять PasteSheet допустимо только при False и неизменном числе листов;
частично выполненную вставку нельзя повторять вслепую.

Неудачные подходы: отдельное копирование листа с родителем разреза на другом листе
могло вернуть True без нужных видов; исключение разрезов не решает задачу.
Не планировать ручное восстановление через выдуманный SetBaseView или EditPaste:
используется существующий `ModelDoc2.Paste`. Сам адрес/подпись разреза после
переименования не доказывает родство. Исходники не сохранять, временные перемещения
выполнять в собственной копии. Это также полезно при компоновке деталей на листах.

## D3. Сохранность оформления и rebuild

`CaptureDrawing`, `AddAnnotationStats`, `VerifyDrawing`, `VerifyAnnotations`
сравнивают модель/конфигурацию, родителя, масштаб/позицию, размеры, штриховки,
аннотации и появление dangling. `GetDimensionCount4` и счётчики не доказывают
сохранение текста или точной формы каждой аннотации — для компонентных заметок
нужна [отдельная проверка](component-notes.md).

В V14 рабочая копия проходила reopen/rebuild, но итоговая копия без rebuild
падала на Hatches/Б-Б. V15 добавила `RebuildDrawing` перед проверкой итоговой копии
и затем подтверждена пользователем. Объяснение конкретного несовпадения как
неактуального состояния штриховок осталось гипотезой, не доказанным диагнозом.
`ForceRebuild3(False)` по нужным листам, fallback EditRebuild3 при фактическом False;
точность проверок не ослаблять. Цена массовых rebuild — [document-output.md](document-output.md).
В раме намеренно встречаются листы с деталями: это допустимые исходные данные.
В мерджере алгоритма постановки новых размеров нет. Отдельный материал
[AutoSizeDrilling](dimensions.md) теперь даёт ограниченный алгоритм для выбранного
ортогонального вида с автоматическими тестами, не native-подтверждением.
