Это **пять областей знаний, а не пять агентов**. Для задачи достаточно одной-двух страниц. Правила координатора: [AGENTS.md](../AGENTS.md). Реальные статусы версий: [evidence.md](evidence.md).

| Область | Читать при задаче | Страница |
|---|---|---|
| Листы, зависимые виды, разрезы | Копирование/объединение/активация | [drawings.md](drawings.md) |

## Роли (три, подключаются по необходимости)
- **`coder`** — реализация (может править только назначенные файлы).
- **`api_expert`** — API-исследование (только чтение).
- **`debugger`** — диагностика/тесты/регрессии (только чтение).

Профили: [agents](../agents/); подключение: [config.toml](../../.codex/config.toml); правила: [agent-setup.md](agent-setup.md).

## Достоверность и накопление знаний
- **Проверено в SolidWorks / подтверждено пользователем** — только конкретная версия и сценарий.
- **Проверено автоматически** — сборка, парсер, interop или тесты без native-испытания.
- **Не проверено** — гипотеза или кандидат; **Не работает** — зафиксирован конкретный отказ.
- Записывай только: дата/версия → причина → решение (файл, функция) → доказательство → ограничения. Не вставляй многословную историю разработки.

**Ориентир:** `drawingmerger/V16_21` — подтверждённый вариант, `V16_22` — кандидат. Для сверловки R7 — подтверждённая точка возврата, R17 — текущий кандидат. Различать релизы и сохранять историю.
