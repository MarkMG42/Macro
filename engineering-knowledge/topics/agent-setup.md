# Три роли Codex — краткая маршрутизация

Главный Codex координирует задачу; роли доступны через [config.toml](../../.codex/config.toml) и `engineering-knowledge/agents/*.toml`. Конфигурация CLI: до 4 потоков (главный + 3), глубина 1. Фактический запуск зависит от клиента.

| Ситуация | Кого использовать |
|---|---|
| Простая правка или ответ | Сам главный агент, без подагентов |
| Реализация существенного изменения | `coder` |
| Неизвестный метод SolidWorks, COM-контракт | `api_expert` |
| Ошибка, журнал, регрессионная проверка | `debugger` |
| Сложная ошибка API и кода | `api_expert` + `debugger`, затем при необходимости `coder` |

Каждому дать **конкретные файлы и вопрос**, запрет массового чтения, требование назвать доказательство и ограничения. `api_expert` и `debugger` — read-only; `coder` получает отдельные пути записи. Главный агент объединяет решения и проверяет результат. Подагенты не порождают подагентов и не публикуют изменения.

Предметные знания остаются в [каталоге](README.md), а не копируются в инструкции ролей. Проверка структуры: `python3 engineering-knowledge/tools/check_agent_knowledge.py`; native SolidWorks-тест проводится отдельно.
