# Сохранение, PDF и производительность

## O1. PDF после проверки чертежа

Задача: получить PDF объединённого многолистового документа. Реализация:
[helpers.vba](../../drawingmerger/V16_21/tools/helpers.vba) `ExportDrawingToPDF`,
[merge_core.vba](../../drawingmerger/V16_21/tools/merge_core.vba) `main`.
Статус: используется в V17 с описанным SUCCESS и в подтверждённой V21;
отдельная визуальная/постраничная проверка PDF в облаке не выполнена.

API: `GetExportFileData(1)` → ExportPdfData, `ExportAs3D=False`,
`ViewPdfAfterSaving=False`, `ModelDocExtension.SaveAs(pdfPath,0,1,pdfData,errors,warnings)`.
В текущем рабочем пути **SetSheets не вызывается**. Это факт проверенной реализации,
не утверждение о неработоспособности SetSheets. Для выборочного экспорта изучить
его актуальную сигнатуру и отдельно испытать набор/порядок листов.

Проверки: передан сохранённый drawing, задан путь; Boolean успеха, errors=0,
непустой созданный файл. Warnings журналируются. Сначала приватный WORK_PDF,
затем публикация. Эти проверки не удостоверяют содержимое/число страниц.
Для пакетной конвертации можно повторно использовать этот контракт, но цикл
открытия/закрытия, список файлов и восстановление состояния требуют отдельной
реализации и испытания. Полного доказанного batch-конвертера в текущем Git нет.

## O2. Измерять этапы, не обвинять копирование без данных

[V18 README](https://github.com/MarkMG42/Macro/blob/82829abf353002d76593c05f49232c421d9a9d15/V16_18/README_RU.md) описывает реальный SUCCESS V17:
25 листов, 70 видов, 11:53 с выбором/загрузкой. Все семь источников передавались
напрямую, без SOURCE-копий. Один rebuild+verify занял 1:44, Save3 — 0:34;
close/copy/open/rebuild/verify — 2:42, второй Save3 — 0:14; PDF/завершение — 0:13.
Это измерение одного комплекта; не доказано, что копирование было основной причиной.

V18–V21 создают итоговый MERGED сразу из байтовой копии основного, перестраивают
новые листы после источника и выполняют один Save3 по умолчанию. Код:
`main`, `RebuildDrawing`, `PrepareSource` (ссылки выше и
[source_properties.vba](../../drawingmerger/V16_21/tools/source_properties.vba)).
`VERIFY_AFTER_SAVE=False` проверяет **открытый документ после Save3**; это не
независимая проверка сохранённого файла после открытия. True включает дорогой
close/open/rebuild/verify/Save3. Оптимизацию проверили автоматически, измеренного
универсального ускорения нет; V21 позднее подтверждена пользователем.
Копия источника для межлистового семейства нужна алгоритму [D2](drawings.md),
её нельзя просто удалить ради скорости. Сохранять проверки, сокращать повторную работу.

## O3. Запись прямо в основной документ — новый режим V22

Статус: Проверено автоматически; **Не проверено в SolidWorks**. Реализация:
[V22 merge_core.vba](https://github.com/MarkMG42/Macro/blob/82829abf353002d76593c05f49232c421d9a9d15/V16_22/tools/merge_core.vba) `PrepareMainDrawing`,
`CheckSavedInput`, `RequireOwnedPath`, `main`; [инструкция](https://github.com/MarkMG42/Macro/blob/82829abf353002d76593c05f49232c421d9a9d15/V16_22/README_RU.md).

До правок: запрет несохранённых изменений/readonly, копия на диске в
`runs/<run>/BACKUP_MAIN.slddrw`, проверка существования и размера. Затем исходный
документ — target, его путь/имя не меняются, Save3 по проверенному результату.
Exact allowlist допускает только выбранный основной файл вне приватного runFolder.
`IsOpenedReadOnly` — действительный метод; GetReadOnlyState не использовать.
PDF получает отдельное имя с временем. Добавляемые оригиналы не сохраняются.

FAILED не вызывает дополнительный Save3 непроверенного основного документа.
Но если Save3 уже начался, диск мог измениться: автоматического отката нет.
Резервная копия проверена по размеру, это не транзакционная гарантия. Для ручного
восстановления закрыть основной без сохранения и заменить его backup по прежнему
пути (не открывать backup из runs как полноценный оригинал с иным каталогом ссылок).
Повторный запуск на объединённом основном повторно добавляет листы.
Прежние частичные FAILED-checkpoints не считать готовым итогом; ошибка PDF после
Save3 также не означает, что основной откатился. Для безопасного независимого
результата сохранена подтверждённая V21 с отдельным MERGED.

## O4. R17: измерение скорости сверловки

29.10.2026, статический аудит профиля sw_document_output. В
`weldment_drilling/InsertWeldWithHoles.txt` `WriteLog` формирует строку один
раз для Immediate и файла, сохраняя `Open/Print/Close` на каждую запись ради
аварийной диагностики. `start` записывает `Timer`-время таблицы, видов,
размеров с разрывами, позиций и всего цикла после первого диалога; переход
через полночь учитывается. Дополнительный `InputBox` шаблона попадает во время
таблицы и делает такой запуск непригодным для сравнения. Проверено лишь
автоматически, не профилировано в SW2025. Для оценки ускорения запускать R16
и R17 на одинаковых копиях модели/чертежа с одинаковым шаблоном несколько раз,
сравнивать медиану полного времени и каждого этапа при совпадении числа видов,
размеров, разрывов, выносок, значений и компоновки. Цель 25% не доказана.
