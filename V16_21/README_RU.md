# V16.21 — нативный адрес заметки разреза

BUILD_ID: MERGE_DRAWINGS_V16_21_NATIVE_SECTION_ADDRESS_20261028

## Обновление

Заменить только стандартный модуль текстом MERGE_DRAWINGS_V16_21.txt,
выполнить Debug → Compile и сохранить .swp. Форму frmDrawingOrder не менять.
Альтернатива — удалить старый стандартный модуль и импортировать MergeDrawingsV16_21.bas
(Windows-1251). Не оставлять два main.
При первой установке создать макрос .swp со стандартным модулем и пустой UserForm
с (Name)=frmDrawingOrder; вставить FORM_CODE.txt в код формы.

## Подтверждённая ошибка V16.20

Расширенный аудит показал различие между отображаемым именем разреза и GetUniqueName.
Например, Б-Б в результате имеет внутреннее имя «Чертежный вид23».
Component.Name2 корневой модели также не содержит полный адрес служебных экземпляров.
Построенная V16.20 ссылка записывалась, но не разрешялась; текст оставался пустым.

DrawingComponent.Name самой привязки содержит полную цепочку сгенерированной
SectionAssembly, экземпляра сборки и экземпляра детали. В результате меняются имя
служебной сборки и номера экземпляров; у А-А и Б-Б цепочки различаются.

V16.21 использует эту нативную цепочку и View.GetUniqueName. Родительский контекст
каждого следующего звена — имя предыдущего без конечного номера экземпляра «-число».
Служебная сборка сохраняется. Свойство и остальной текст выражения не подменяются.
Изменение применяется к пустой ссылке SectionAssembly с непустым исходным текстом,
ровно одной геометрической привязкой и одним $COMP. Контекст компонента сверяется
с исходной привязкой по пути модели, конфигурации и имени экземпляра.

Строгие проверки выражений, текста, слоёв и привязок сохранены. В журнале есть
SECTION NOTE native address и SECTION NOTE rebuilt. Неоднозначный или неподдерживаемый
случай останавливает обработку. Разрешимость нового адреса и непустой исходный текст
по-прежнему проверяются после перестроения — успех присваивания строки недостаточен.

## Что проверено

На данных нативного аудита построение адреса исходного А-А точно воспроизводит
имеющееся рабочее выражение. Для результата проверены разные внутренние имена видов,
сохранение сгенерированных служебных сборок и разные экземпляры деталей А-А/Б-Б.
Это проверка формата по отчётам, не запуск VBA/SOLIDWORKS. Грамматика, API interop
и сборка архива также проверены. Нативный результат требует повторного запуска.
Личные отчёты в репозиторий не включены.

Сортировка, перенос разрезов, источники свойств листов и ускоренное сохранение
не менялись. MERGED создаётся рядом с основным чертежом; оригиналы защищены.
SOURCE-копия нужна только при зависимых видах на разных листах.
VERIFY_AFTER_SAVE=False по умолчанию: один Save3, проверка открытого документа,
PDF, без повторного открытия. True включает более медленную проверку после открытия.
Первый результат проверьте также после ручного открытия.
При FAILED частичный MERGED не считается завершённым результатом.
