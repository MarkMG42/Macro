# V16.17 — меньше повторной обработки, локальный источник свойств, связанные заметки

BUILD_ID: MERGE_DRAWINGS_V16_17_LOCAL_PROPERTY_NOTES_20261027

Это новый вариант для проверки в SOLIDWORKS. Рабочая V16.15 и V16.16 не изменены.

## Установка обновления

В существующем .swp заменить **только стандартный модуль** содержимым
MERGE_DRAWINGS_V16_17.txt. Выполнить Debug → Compile, сохранить .swp, запустить main.
Форму frmDrawingOrder и её код менять не нужно. Альтернатива — удалить старый
стандартный модуль и импортировать MergeDrawingsV16_17.bas (Windows-1251).
Не оставлять два модуля с main/OrderPickFiles/OrderFolderFiles.

Для первой установки создать макрос в SOLIDWORKS, вставить стандартный модуль,
добавить пустую UserForm с (Name)=frmDrawingOrder и вставить FORM_CODE.txt в код формы.
Элементы формы создаются автоматически. Поставка содержит исходники, не бинарный .swp.

## Почему остановился предыдущий запуск

В журнале V16.16 нет вызова сохранения: обработка прервалась на седьмом источнике,
«Рама». Лист с видом детали наследовал источник свойств от сборки на другом листе.
При попытке назначить вид той сборки в объединённом документе SOLIDWORKS вернул
«По умолчанию» и выбрал локальную деталь. Проверка правильно обнаружила замену модели.

Если нужного вида на листе нет, V16.17 создаёт скрытый служебный вид требуемой
модели/конфигурации на этом листе и назначает его источником свойств. Служебный вид
виден в дереве чертежа, но его геометрия скрыта; это обычный нативный вид, не картинка.
Проверяются модель, конфигурация, отсутствие родителя и скрытое состояние, в том числе
после повторного открытия. Режим показа скрытых видов в результате отключается,
чтобы служебная геометрия не показывалась. Если API не создаст вид или не примет его как источник,
проверка остановит обработку, не подменяя сборку деталью.

## Скорость и источники

- Источник, у которого все семейства видов находятся на своих листах, копируется
  в результат прямо из исходного документа без отдельного SOURCE_….slddrw.
  Закрытый источник открывается только для чтения. Ранее открытый документ остаётся
  открытым; восстанавливается активный лист. Источник не сохраняется и не перестраивается.
- Если родитель и разрез/выносной вид находятся на разных листах, сохраняется рабочая
  копия: в ней временно собирается семейство видов перед PasteSheet. Это необходимо
  для прежнего способа сохранения связей и исключает вырезание видов из оригинала.
- После каждого источника перестраиваются только его новые листы. При сопоставлении
  очередного вставленного листа читается только этот лист, а не весь документ.
- Перед сохранением перестраивается и проверяется весь результат. Сохраняются рабочий
  файл, его побайтовая копия рядом с чертежами, повторное открытие, полная проверка и PDF.
  Убран дополнительный промежуточный цикл открытия/перестроения/сохранения рабочей копии.

Время обработки зависит также от загрузки сетевых моделей. Ускорение на конкретном
компьютере ещё не измерялось. В журнал добавлены начала операций SAVE.

## Связанные наименования

Для заметок с $PRPSMODEL и $COMP сохраняются исходный вычисленный текст, выражение,
координаты, слой, видимость и компоненты привязок (путь, конфигурация, имя экземпляра).
После переноса выражение назначается повторно с заменой @старый_вид/ на @новый_вид/
только внутри $COMP. Замены не каскадируют. Слой и видимость восстанавливаются.
Назначение допускается только при однозначном совпадении заметки по выражению и
координатам и при неизменности компонентов привязки. Привязка к другой детали
автоматически не угадывается. Вычисленный текст не подставляется вместо живой ссылки.

После перестроения и повторного открытия проверяются выражение, привязки, слой,
видимость и исходно непустой текст. Пустая заметка не считается успешным результатом.
Это попытка исправить обнаруженные устаревшие имена видов и слой назначения; ещё
не доказано, что она устраняет все случаи потери текста на других компьютерах.
Не поддержанная API привязка или неоднозначное совпадение останавливает проверку.
Заметки с другими типами выражений остаются под прежними проверками числа аннотаций.
Конфликты одноимённых слоёв с разными свойствами между документами не разрешаются
автоматически. Диагностика не заменяет визуальную проверку.

## Файлы и ошибка

Итоговые MERGED_<дата>_<время>.slddrw и .pdf находятся рядом с ОСНОВНЫМ чертежом.
Рабочая копия основного чертежа, временные источники при необходимости, merge.log,
STATUS.txt и verified_views.tsv — в runs/<дата>_<время>. Существующие файлы
не перезаписываются; автоматический поиск пропускает предыдущие MERGED_….

При ошибке рабочий чертёж не закрывается. Для файла внутри runs выполняется попытка
Save3 с записью результата в журнал (FAILED CHECKPOINT). STATUS остаётся FAILED:
это непроверенный частичный результат, его нельзя выдавать за готовый чертёж.
Если сам Save3 не сработает, документ остаётся открытым для ручного сохранения.

## Проверки здесь

Проверяются грамматика VBA 7.1, наличие и сигнатуры новых API в библиотеке SOLIDWORKS,
BAS/TXT, лимиты строк и продолжений, уникальность процедур, неизменность формы и
защита исходных файлов. Архив проверяется на целостность и соответствие исходникам.
Windows, нативная компиляция VBA и запуск SOLIDWORKS здесь недоступны. Проверка в вашей
SOLIDWORKS 33.4.1 обязательна: сначала один источник, затем полный набор с «Рамой»,
включая разрезы, наименования, штампы, отсутствие служебной геометрии в PDF и повторное
открытие результата. При ошибке прислать merge.log и STATUS.txt; рисунок результата,
если возможно, особенно полезен для сравнения пустого GetText и изображения на экране.
