# V16.22 — сохранение в основной чертёж

BUILD_ID: MERGE_DRAWINGS_V16_22_MATCH_RESTORE_20261107

## Обновление

Заменить только стандартный модуль текстом MERGE_DRAWINGS_V16_22.txt,
обновить код формы frmDrawingOrder из FORM_CODE.txt,
выполнить Debug → Compile и сохранить .swp. Оба файла нужно обновить.
Альтернатива — удалить старый стандартный модуль и импортировать MergeDrawingsV16_22.bas
(Windows-1251). Не оставлять два main. При первой установке создать .swp со стандартным
модулем и пустой UserForm с (Name)=frmDrawingOrder; вставить FORM_CODE.txt в код формы.

## Сохранение

Выбранный ОСНОВНОЙ чертёж теперь редактируется и сохраняется по своему прежнему пути,
с прежним именем. Отдельный MERGED_….slddrw не создаётся. Исходники, добавляемые к
основному чертежу, по-прежнему не перезаписываются. Открытые файлы с несохранёнными
изменениями нужно сохранить до запуска; основной файл должен быть открыт для записи.

Перед открытием/изменением основного документа его сохранённое содержимое
копируется в runs/<дата>_<время>/BACKUP_MAIN.slddrw. Если копирование не удалось,
изменение основного документа не начинается. Проверяются наличие и размер копии.
Это резервная копия для восстановления, не отдельный результат объединения.

После объединения и проверки выполняется Save3 основного документа. По умолчанию
VERIFY_AFTER_SAVE=False: после Save3 проверяется открытый документ без закрытия и
повторного открытия. True включает дополнительную медленную проверку после открытия.
PDF создаётся рядом: <имя основного>_MERGED_<дата>_<время>.pdf, чтобы не перезаписать
существующий PDF. Журнал, STATUS.txt и verified_views.tsv — в папке запуска.
Для межлистовых семейств разрезов всё ещё могут создаваться временные SOURCE-копии.

## Если произошла ошибка

Основной документ остаётся открытым. Автосохранение при FAILED отключено: частичный
результат дополнительно не записывается в исходный файл. Если ошибка возникла уже
после начала Save3 (например, при проверке после сохранения или экспорте PDF), файл
на диске мог измениться. Состояние FAILED не означает автоматический откат.

Чтобы вернуть исходное состояние, закрыть основной документ без сохранения,
затем скопировать BACKUP_MAIN.slddrw поверх основного файла по его прежнему пути.
Не заменять открытый в SOLIDWORKS файл. Простое открытие резервной копии из runs
может иначе разрешать относительные ссылки; восстанавливать нужно в исходную папку.

Повторный запуск на уже объединённом основном чертеже добавит выбранные листы ещё раз.
Для повторения прежнего объединения сначала восстановить резервную копию.

## Исправления 07.11.2026

Ошибка «Неоднозначный или потерянный вид; совпадений=0» возникает до Save3,
на этапе сопоставления вставленных видов. В прежнем коде координаты, масштаб и
угол сравнивались до RestoreView, который должен их восстановить. Новый код
сначала ищет точное совпадение; при нуле совпадений допускает другое размещение,
только если остальные признаки и родитель дают ровно одного кандидата.
Неоднозначность по-прежнему останавливает объединение. После восстановления
положения и перестроения выполняется исходная строгая итоговая проверка.
Отсутствие разреза не запрещено. Без исходного чертежа и merge.log нельзя
подтвердить, что именно размещение было причиной ошибки на скриншоте.
При следующем отказе журнал теперь содержит признаки всех кандидатов.

В окне сортировки показаны только имена с расширением. Полные пути сохраняются
внутри списка для открытия, перестановки и проверки дублей. Одинаковые имена из
разных папок остаются отдельными файлами и могут выглядеть одинаково.

Убраны начальное принудительное перестроение всех листов основного чертежа и
повторный полный снимок сразу после него: до импорта эти листы не изменялись.
При сборке межлистового семейства в SOURCE-копии перестраиваются только листы,
затронутые переносом. Вставленные листы перестраиваются один раз после полного
восстановления. Полная проверка результата сохранена; ускорение в SW не измерено.
Сохранение выполняется в выбранный основной .slddrw через Save3; отдельный
MERGED.slddrw не создаётся. BACKUP_MAIN — резервная копия, а не результат.

## Проверки

В облаке выполняются:

- check_regressions.py: исполнение выражений VBA fingerprint в Python, модель
  двух проходов сопоставления и статические проверки формы/сохранения/перестроений;
- check_grammar.py: свежий разбор стандартного модуля и кода формы ANTLR VBA 7.1;
- package_release.py: эквивалентность BAS/TXT, кодировки, ограничения строк,
  уникальность процедур, контрольные суммы и проверка содержимого ZIP.

Отчёты находятся в checks. Исторические api.json и native_address_fixtures.json
сохранены как справочные данные предыдущей сборки; новый COM API не добавлен.
SOLIDWORKS и VBA Editor в Linux отсутствуют: Debug → Compile, Save3, визуальная
проверка и замер скорости здесь не выполнялись. V16.21 остаётся прежней
подтверждённой версией и не изменена.

Перед применением к рабочим документам проверить на копиях в SOLIDWORKS 2025:
обычный чертёж без разрезов; разрезы на одном и разных листах; несколько видов
одной модели; одинаковые имена файлов в разных папках. После Compile и запуска
проверить порядок листов, размещение, размеры, штриховки, живые заметки, PDF;
закрыть и повторно открыть основной файл, убедиться в сохранности добавленных
листов и отсутствии нового MERGED.slddrw. Исходники должны остаться неизменными.

Общая проверка engineering-knowledge/tools/check_agent_knowledge.py не проходит:
она сверяет сохранённые исторические manifests, поэтому отмечает обновлённую
V16_22 и уже существующие расхождения в других проектах. Другие проекты не
исправлялись. Это не проверка синтаксиса VBA. Diff проверен с учётом обязательных
CRLF в поставляемых BAS/TXT.
