# V16.13 — сохранить исходную модель свойств на добавленных листах

BUILD_ID: MERGE_DRAWINGS_V16_13_LOCAL_PROPERTY_SOURCES_20261027

## Обновление

После V16.11/V16.12 заменить только стандартный модуль содержимым
MERGE_DRAWINGS_V16_13.txt, выполнить Debug → Compile, сохранить .swp, запустить main.
Форма frmDrawingOrder и FORM_CODE.txt не изменились; форму пересоздавать не нужно.
При импорте BAS удалить предыдущий стандартный модуль, не оставлять дубли main.
Использовать исходные сохранённые чертежи, не WORK_TARGET/SOURCE прошлого запуска.

Для первой установки создать .swp, вставить основной модуль, добавить пустую
UserForm с (Name)=frmDrawingOrder и вставить FORM_CODE.txt в код этой формы.
Кнопки создаются внутри VBA, внешнее скриптовое окно не используется.

## Подтверждённая причина

Журнал V16.12 выявил реальное изменение: источник свойств добавленного листа
сменился с исходной сборки на сборку основного чертежа. Оба документа имели
MatchPropertySheets=True, PropertySheetNo=1. Сохранение общего наследования
после объединения заставило добавленные листы ссылаться уже на первый лист
итогового документа, где находится другая модель. Проверка V16.12 правильно
остановилась. Простое удаление этой проверки дало бы неверные данные штампа.

V16.13 для всех добавляемых листов устанавливает SameCustomProp=False и явный
источник свойств. Его выбирают по ORIGINAL-снимку до изменений, не по случайному
виду в результате. При исходном наследовании:
1. Берётся прежний EffectivePropertyView.
2. Если он на этом листе, используется он.
3. Иначе ищется местный вид с точно той же моделью и конфигурацией.
   Разные виды одной модели/конфигурации эквивалентны для чтения этих свойств.
4. Если местного соответствия нет, запрашивается прежний источник с другого
   листа. Поддержку такой ссылки должны подтвердить стандартные readback и
   проверки после перестроения; при отказе выполнение останавливается.

Имя преобразуется через уже проверенную карту viewMap. Для исходного локального
режима сохраняется прежняя логика имени. В ожидаемом снимке добавленного листа
режим теперь тоже False, но PropertyModel/PropertyConfiguration остаются из
оригинала. Исходный основной лист и настройки документа не меняются.

PROPERTY SOURCE localize и PROPERTY MODE показывают выбранный вид и отключение
наследования. Строгие проверки модели/конфигурации, имени локального вида и режима
сохраняются до/после сохранения и повторного открытия. Геометрия, связи разрезов,
оформление и экспорт PDF проверяются как раньше. Передача CAD-файлов в GitHub
не выполнялась; в комплекте только исходники макроса и инструкции.

## Проверка результата

Для текущего комплекта ожидаются 5 листов, оба связанных разреза, исходные модели
источника свойств на добавленных листах, SUCCESS и итоговые SLDDRW/PDF.
После успешного запуска сравнить заполненные штампы с исходными чертежами.
При ошибке нужен полный merge.log, особенно PROPERTY SOURCE и PROPERTY MODE.

Здесь проверены грамматика модуля, эквивалентность BAS/TXT, лимиты строк,
уникальность процедур, область изменений, неизменность формы и PDF-экспорта,
целостность ZIP/SHA-256. Нативная компиляция VBA, выполнение назначения источников
в SOLIDWORKS и проверка Defender здесь недоступны. Исходники не являются готовым
бинарным .swp. При блокировке защитой не обходить её.
