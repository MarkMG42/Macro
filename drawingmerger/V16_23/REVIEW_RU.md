# Проверка V16.22 и изменения кандидата V16.23

Прочитаны корневой AGENTS.md, правила координатора, каталог знаний, темы drawings / document-output / vba-com / component-notes / evidence, README и инструкция drawingmerger, модуль и код формы из рабочего архива. Старые темы знаний местами описывают V16.22 как неподтверждённую и с бэкапом; текущие README и исходник рабочего архива новее: V16.22 подтверждена 11.11.2026, бэкап основного отключён. Для новой версии выбран фактический рабочий архив.

## Что найдено и изменено

| Участок | Наблюдение | Решение |
|---|---|---|
| `RebuildDrawing` | В V16.22 уже нет полного финального rebuild, повторной попытки при False и rebuild при ActivateDoc3. Единственный явный ForceRebuild3 вызывается для листов чертежа. Прямого перестроения ReferencedDocument/сборки нет. | Сохранён один проход по добавленным листам и необходимый проход по изменённым листам SOURCE-копии. Добавлена проверка типа документа до rebuild. Простая замена False на True не доказывает ускорение чертежа: TopOnly документирован для сборок. |
| Выбор листов rebuild | Для каждого листа линейно просматриваются все значения словаря. | Однократный индекс имён; поиск O(1), проверка отсутствующих имён. Порядок листов сохраняется. |
| `AppendDrawing` | Даже для directSource повторно ищутся все виды через полный GetViews, хотя PrepareSource уже доказал отсутствие межлистовых переносов. | Этот обход выполняется только для приватной SOURCE-копии; сопоставление вставленных видов и итоговые проверки сохранены. |
| `main` | Один и тот же неизменённый снимок повторно сравнивается перед Save3. | Убрано повторное сравнение. Проверки после каждого источника, свежий снимок после Save3 и опциональное повторное открытие сохранены. |
| Неиспользуемый код | GetSaveFileNameW, OFN_OVERWRITEPROMPT, локальная GetBaseName, записываемая без чтения targetPath, неиспользуемые drawing в AppendDrawing и props в MoveView. | Удалены только из нового модуля. fsoRun.GetBaseName нужен и сохранён. Удалены проверки коллизий со старыми именами MERGED в InitRunFolder: таких выходов больше нет. |
| PDF | Автоматический экспорт уже присутствует. Проверяется итоговый путь, который может содержать старый файл; большая часть диагностики идёт только в Debug.Print. | Новый WORK_PDF, явный список всех листов через SetSheets, журнал экспорта, резерв предыдущего PDF перед публикацией и попытка восстановления при отказе публикации. |
| Итоговые сообщения | Длинные сообщения не соответствуют запросу. | Точные строки «выполнено успешно» и «ошибка, проверьте журнал»; подробности остаются в журнале. |
| Ранняя ошибка | При отказе до открытия журнала сообщение «проверьте журнал» могло вести к отсутствующему файлу. | Добавлена попытка создать резервный журнал в `%TEMP%/DrawingMerger_V16_23/runs`. |

Количество необходимых явных перестроений относительно рабочего V16.22 не уменьшено: дополнительных лишних вызовов в этой версии не найдено. Сокращены другие повторные операции. Проверка типа документа запрещает прямой rebuild сборки этим макросом, но не доказывает отсутствия внутренних обновлений SOLIDWORKS при открытии, переключении листов, Save3 и экспорте.

## Что оставлено намеренно

- SOURCE-копии для семейств разрезов между листами нужны для native-переноса связей. Удалять их ради скорости нельзя без другого проверенного алгоритма.
- Полные проверки после каждого источника потенциально дороги, но обнаруживают влияние импорта на ранее добавленные листы.
- Перестроение новых листов нужно для штриховки и зависимых видов. Удаление требует native-испытания, а прежние версии имели регрессию штриховки.
- Скрытые служебные виды обеспечивают правильный источник свойств штампа; это не мусорные элементы.
- Допуск размещения 30 мм и специальное исключение RD18 = 532 мм у конкретной модели — унаследованные правила рабочей версии. Не расширены и не удалены.
- Форма не изменена. Диалоги ошибок при добавлении файлов остаются её локальными пояснениями; запрошенные строки относятся к итоговому результату запуска.

## Возможные следующие оптимизации

1. Измерить полное время CaptureDrawing/FindView/VerifyDrawing, открытия и переключения листов на реальном комплекте. Сейчас добавлены только таймеры rebuild и PDF; процент ускорения не заявляется.
2. Индексировать живые COM-виды на коротком неизменяемом этапе. После EditCut/Paste такой кэш надо сбрасывать: удалённые COM-ссылки нельзя использовать.
3. Проверять инкрементально только добавленные листы, оставив финальный полный аудит. Это меняет момент обнаружения повреждений и требует отдельного испытания.

## API и пределы проверки

Проверены официальные контракты SW2025:

- [ForceRebuild3 / TopOnly](https://help.solidworks.com/2025/English/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.IModelDoc2~ForceRebuild3.html).
- [ExportPdfData.SetSheets: Boolean, Which и массив имён листов](https://help.solidworks.com/2025/English/api/sldworksapi/SOLIDWORKS.Interop.sldworks~SOLIDWORKS.Interop.sldworks.IExportPdfData~SetSheets.html).
- [Тип данных PDF: swExportPdfData = 1](https://help.solidworks.com/2025/english/api/swconst/SolidWorks.Interop.swconst~SolidWorks.Interop.swconst.swExportDataFileType_e.html).

Отчёты в checks фиксируют SHA именно поставляемых файлов. Парсер VBA и статические регрессионные проверки не заменяют Debug → Compile и запуск SW2025. SolidWorks в Linux-среде отсутствует; native-компиляция, реальный PDF, восстановление при блокировке файла и прирост скорости не проверены.

Общий скрипт проверки базы знаний репозитория имеет устаревшие ссылки и обращается к отсутствующему drawingmerger/PRESERVED_FILES.json. Это проблема исходного состояния репозитория, не новой версии. Рабочие файлы и база знаний не менялись ради исправления этого несвязанного аудита.
