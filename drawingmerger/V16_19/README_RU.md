# V16.19 — привязки заметок на разрезах

BUILD_ID: MERGE_DRAWINGS_V16_19_SECTION_NOTE_CONTEXT_20261028

## Обновление

В существующем макросе заменить только стандартный модуль текстом
MERGE_DRAWINGS_V16_19.txt. Выполнить Debug → Compile и сохранить .swp.
Форму frmDrawingOrder и её код не менять. Альтернатива — удалить прежний
стандартный модуль и импортировать MergeDrawingsV16_19.bas (Windows-1251).
Не оставлять два main.

При первой установке создать макрос .swp, вставить стандартный модуль, добавить
пустую UserForm с (Name)=frmDrawingOrder, вставить FORM_CODE.txt в код формы.
В архиве исходники, не готовый бинарный .swp.

## Ошибка и изменение

В полученном журнале V16.18 разрезы А-А и Б-Б перенесены обратно на нужный лист.
Остановка произошла затем на заметке «Детальный элемент169» вида «Разрез Б-Б»:
«Изменилась деталь привязки заметки». До переноса в копию текст заметки совпадал.
Старый журнал не содержал различающихся привязок, поэтому точная причина отличия
по нему не установлена.

V16.19 читает компонент геометрической привязки через Entity.GetDrawingComponent(view)
с контекстом конкретного чертёжного вида. Если компонент не возвращён, остаётся
GetComponent как резервный способ. Компонент и DrawingComponent, возвращённые
непосредственно аннотацией, по-прежнему читаются напрямую.

После однозначного поиска заметки по выражению и координатам сначала обновляется
живая ссылка $COMP на соответствующий вид результата, затем заново читаются привязки.
Это позволяет проверить их после обновления контекста ссылки. Сравнение остаётся
строгим: число привязок, путь модели, конфигурация и имя экземпляра компонента.
При отличии выражение возвращается к значению до попытки, макрос останавливается.
Выноски не перепривязываются, текст не подменяется постоянной строкой.

В merge.log добавлены LINKED NOTE binding before/after и LINKED NOTE expression:
исходная, текущая и требуемая ссылки и обе сигнатуры привязок. Если ошибка повторится,
эти строки позволят отличить потерю выноски от изменения компонента/конфигурации.
Журнал может содержать пути к файлам и текст заметок; не публикуйте его в репозитории.

Алгоритм переноса листов, межлистовых семейств разрезов и скрытых видов свойств,
сортировка и оптимизации сохранения V16.18 не изменены. Новый MERGED создаётся
рядом с основным чертежом, оригиналы не перезаписываются. SOURCE-копия нужна только
для семейств с родителем и зависимыми видами на разных листах.

## Проверка результата

По умолчанию VERIFY_AFTER_SAVE=False: один Save3 и проверка открытого документа
после сохранения, затем PDF. Автоматического повторного открытия нет. Для строгой
проверки после открытия можно включить True (медленнее). Первый результат проверьте
также после ручного повторного открытия, включая наименование в заметке на разрезе.

При FAILED файл MERGED может быть частичным. Он оставляется открытым и выполняется
попытка сохранить его для диагностики; это не завершённый результат.

В облаке проверены грамматика VBA, доступность API в interop и сборка архива.
Нативная компиляция VBA и запуск в SOLIDWORKS здесь недоступны. Устранение именно
этого случая требует повторного запуска на исходных чертежах.
