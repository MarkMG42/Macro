# V16.28: ручная проверка при недостаче размеров

Изменены main (предварительный сбор всех потерь после итогового снимка, отчёт и ранний выход без Save3/PDF) и AppendDrawing (добавление только строковых метаданных происхождения в ожидаемые records). Новые функции CollectDimensionLosses, DimensionReviewText, WriteDimensionReview, DimensionReviewMessage. Геометрия, UI guard, переносы, профиль и все строгие верификаторы не менялись.

При наличии потерь не вызывается VerifyDrawing и не записывается AUDIT OK. Записывается AUDIT NOT PASSED, REVIEW_REQUIRED и review_views.tsv; автоматические сохранения недостижимы по этому пути. Результат остаётся открытым, полный исходный expectedResult не нормализуется и не подменяется фактическими счётчиками. Пользователь предупреждён, что остальные проверки не выполнены и весь результат требует ручной проверки. Это намеренное изменение поведения, а не ослабление VerifyStructure/VerifyAnnotations/SameViewFingerprint или расширение RD18-исключения.

При отсутствии потерь выполняется прежний строгий аудит и сохранение. Промежуточные ошибки копирования/консолидации продолжают останавливать процесс. UI восстановлен до чтения итогового снимка; активирование первого проблемного листа не включает подавление повторно.

Метаданные ReviewSourcePath/ReviewSourceSheet/ReviewSourceView добавляются только в ожидаемые словари после импорта, исходные документы и аннотации не редактируются. Порядковый номер в отчёте берётся из фактического порядка вкладок, а не из текста штампа. Существующий PDF при REVIEW_REQUIRED не обновляется, не удаляется и не переименовывается.

Нужны native-тесты: одна и несколько потерь на разных листах; пропажа размеров в основном и импортированном виде; нормальный комплект без потерь; дополнительные размеры; промежуточная ошибка; доступность полного отчёта; отсутствие автоматического Save3/PDF в REVIEW_REQUIRED; возможность редактировать активный результат после восстановления UI. Статические проверки и парсер не заменяют Compile VBAProject и запуск в SolidWorks 2025.
