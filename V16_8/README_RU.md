# Объединение чертежей V16

Полный VBA-модуль для SOLIDWORKS 2025 x64. Точка запуска — `main`.
Основа диалогов, сортировки и экспорта PDF — предоставленная рабочая версия V12.

V16 переносит родительский вид и зависимые разрезы одной группой: сначала собирает
семейство на одном листе рабочей копии источника, копирует целый лист, затем
возвращает разрезы на соответствующие листы уже внутри итогового документа.
Порядок листов источника сохраняется. Листы с разрезами не пропускаются.

**Статус проверки:** исходный модуль подготовлен, синтаксис и обращения к API
проверены доступными средствами. Запуска VBA и испытания на настоящем SOLIDWORKS
здесь не было: на этом Mac отсутствует Windows/SOLIDWORKS, а в исходной папке
переданы тексты макросов и описание случая, без самих SLDDRW и связанных моделей.
Нельзя считать сохранение ассоциативности в CAD подтверждённым до такого запуска.

## Установка

1. Распакуйте архив в папку `macro` на Windows с SOLIDWORKS 2025 x64.
2. В SOLIDWORKS выберите **Сервис → Макрос → Создать**. Сохраните новый `.swp`
   внутри распакованной папки `V16`, чтобы результаты также оставались внутри `macro`.
3. В редакторе VBA откройте созданный стандартный модуль и **полностью замените**
   его содержимое текстом из `MERGE_DRAWINGS_V16.txt`, открытого как UTF-8.
   Альтернатива: удалите автоматически созданный пустой модуль и импортируйте
   `MergeDrawingsV16.bas` через **File → Import File**. BAS имеет кодировку Windows-1251
   для русского редактора VBA. Импортировать TXT как BAS не нужно.
4. В **Tools → References** должны быть включены библиотеки типов и констант
   SOLIDWORKS 2025. Установочные DLL из интернета для этого не требуются.
5. Выполните **Debug → Compile**, сохраните `.swp`, запустите `main`.

В поставке находятся исходники `.bas`/`.txt`. Двоичный `.swp` создаётся редактором
SOLIDWORKS; переименование текстового файла в `.swp` не создаёт рабочий макрос.

## Использование

Перед запуском сохраните исходные чертежи и изменения в их моделях. Чертежи должны
быть полностью разрешены, модели доступны по исходным путям. Открытый чертёж с
несохранёнными изменениями отклоняется: рабочая копия создаётся из файла на диске.

Выберите основной чертёж, затем источники из его папки или вручную. В окне списка
перетащите строки в нужном порядке; можно убрать файл или добавить другую папку.
Основной чертёж остаётся первым. Повторные пути и временные `~$`-файлы исключаются.

Результат создаётся рядом с `.swp`:

```text
runs/20261027_001500/
  MERGED_20261027_001500.slddrw
  MERGED_20261027_001500.pdf
  STATUS.txt
  merge.log
  verified_views.tsv
  WORK_TARGET_20261027_001500.slddrw
  SOURCE_20261027_001500_0001.slddrw
  ...
```

Успешное завершение обозначается сообщением макроса и строкой `SUCCESS` в `STATUS.txt`.
Рабочие копии и файлы окна списка сохраняются для диагностики. При ошибке будет
`FAILED` с причиной; такой запуск нельзя принимать как завершённое объединение.
Предоставленные исходники не перезаписываются. Макрос не удаляет файлы.

## Что контролирует сам макрос

- Каждый родитель из `GetBaseView` существует, циклов нет; перед копированием всё
  семейство находится на одном листе.
- После вставки добавлен ровно один лист; число и типы видов, ссылки на модели,
  конфигурации и конкретные родители совпадают с исходным снимком.
- Сохраняются порядок листов, бумага, масштабы, положения, угол, режим масштаба,
  блокировка и выравнивание видов, настройки разрезов и число штриховок.
- Сверяются количества размеров/аннотаций и отсутствие новых висячих аннотаций.
  Проверка наличия геометрии использует габарит вида; полной проверки топологии нет.
- Проверки повторяются после сохранения и повторного открытия результата.
  Только после них выполняется сохранённый из V12 экспорт PDF.

При потере вида или связи обработка останавливается с журналом. Если два вида
невозможно однозначно различить по родителю, модели, конфигурации, ориентации,
положению, масштабу и параметрам разреза, макрос также остановится, не выбирая
родителя наугад. Специальные типы видов, отсоединённые/неразрешённые чертежи и
нестандартные надстройки не заявлены как испытанные.

Для описанного случая ожидаются 9 листов: 5 основного документа и 4 источника.
На третьем добавленном листе должны сохраниться оба разреза А-А/Б-Б с родителем
из второго добавленного листа. Фактические имена после вставки могут измениться
из-за совпадений; в журнале есть строки `MAP` и `LINK OK` с точным соответствием.
